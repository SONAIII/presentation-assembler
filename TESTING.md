# Тестирование скилла presentation-assembler

Скилл собирает брендированные .pptx-деки из дизайнерских шаблонов Яндекса —
«Еда» и «Городские сервисы» (каталоги семейств — `references/families-eda.md`
и `references/families-gor-services.md`). Парадигма fill-first: готовые слайды
заполняются 1:1, генерация — только там, где готового слайда нет.

## Что нужно на машине

Быстрая самодиагностика всего списка ниже — одной командой:

```bash
sh scripts/run.sh scripts/preflight.py           # ✓/⚠/✗ по каждому пункту + чем чинить
sh scripts/run.sh scripts/preflight.py --render  # + проба реального PowerPoint-рендера
                                       # (запустит PP; ловит лицензию/Automation
                                       # до первой сборки)
```

- **Рендер — два уровня** (quality-gates.md §4): пиксель-приёмка — macOS +
  Microsoft PowerPoint (PP должен хотя бы раз запускаться — лицензия);
  скрининг на любой ОС — LibreOffice (классы расхождений и перепроверка
  мерой — `references/lo-render-quirks.md`). qlmanage для приёмки запрещён.
  Сборка и машинные гейты от рендера не зависят и работают везде.
- **Шрифты YS** (YS Text, YS Geo) установлены в систему — без них глиф-замеры
  и рендер дадут другую картинку. Первая же сборка скачает и установит их сама
  (в `~/Library/Fonts`); вручную — `sh scripts/run.sh scripts/fetch_template.py --fonts`,
  либо, если в раздаче есть `Templates/eda/fonts-ys.zip`, распакуйте и
  установите двойным кликом. **Windows — только руками через проводник**
  (выделить все → ПКМ → «Установить»): автокопирование шрифт не активирует,
  и PowerPoint молча подменит типографику.
- **python3** c пакетами: `python-pptx` (1.0.2), `Pillow`, `PyMuPDF` (для рендера).
  Нет Python ≥3.11 — укажи установленный runtime через
  `PRESENTATION_ASSEMBLER_PYTHON=/path/to/python3`; bootstrap также умеет взять
  bundled Codex runtime. Сам Command Line Tools он не устанавливает. После
  выбора Python bootstrap ставит locked-пакеты и прогоняет preflight.
  **Windows:** python — `winget install -e --id Python.Python.3.12` (или
  python.org), пакеты — `python -m pip install python-pptx==1.0.2 Pillow PyMuPDF`;
  шрифты YS — только руками (см. выше). Linux: движок сканирует шрифты рекурсивно
  (`~/.local/share/fonts`, `~/.fonts`, системные каталоги).
- **Платформы.** Обкатано на macOS (сборка + пиксель-приёмка). Windows:
  ядро сборки (fill/structure) работает при шрифтах, установленных руками;
  кастом-ветка (family:custom) и PowerPoint-приёмка недоступны, рендер —
  LibreOffice при наличии; в бою не обкатано — баги с Windows помечайте
  платформой в отчёте.
- **Сеть при первой сборке.** Раздача идёт без тяжёлого .pptx: движок сам
  скачает шаблон (~27МБ) с публичной полки Я.Диска (без авторизации, VPN не
  нужен), сверит md5 по пину из `Templates/manifest.json` и закэширует в
  `~/.cache/presentation-assembler/` — дальше всё офлайн. Без сети: запросите
  файлы шаблона у команды (тикетом в VISCOMMSSKILLS) и положите в
  `Templates/eda/` — адреса полок в манифесте хранятся кодированными,
  руками по ссылке их не скачать.
- **Папка скилла `presentation-assembler` — самодостаточна** (источник правды):
  движок `lib/`, спеки `layouts/` и все скрипты
  (`build_deck.py`, `render.py`, `fetch_photo.py`, `fetch_template.py`,
  `inventory_template.py`) лежат внутри. Положите её в
  `~/.claude/skills/` копией или симлинком:
  `ln -s <путь>/presentation-assembler ~/.claude/skills/presentation-assembler`
- Crash-чекер вендорен внутрь (`scripts/check_pptx.py`) — отдельный скилл
  pptx-crash-check ставить не нужно; диагностика «Repair»-диалога и реестр
  паттернов порчи — `references/pptx-crash-check.md` и
  `references/pptx-crash-known-issues.md`.

## Быстрый старт

Основной сценарий — через Claude Code: попросите «собери презентацию …» /
«сделай дек …» — скилл триггерится сам, спросит шаблон, покажет план (STOP),
соберёт, отрендерит и покажет (STOP). Другой агент (не Claude) — скилл тоже
работает: как подключить, см. [README.md](README.md), секция «Как подключить».

Руками, без агента:

```bash
cd <папка-скилла>
sh scripts/run.sh scripts/build_deck.py examples/mini_deck.json -o /private/tmp/mini.pptx
```

Сборка сама гоняет гейты: crash-check → lint (overflow по глифам) →
composition-чекеры. `⚠ overflow: [слот] — REWORD` = сократи/переформулируй
текст слота и пересобери (кегль не сжимаем — это правило дизайна).

Рендерить строго из `/private/tmp` (TCC-грабли macOS):

```bash
sh scripts/run.sh scripts/render.py /private/tmp/mini.pptx --dpi 110
```

## Эталонные спеки (examples/)

| Файл | Что показывает |
|---|---|

| `smoke_A_text.json` | 12 слайдов: структурные + текстовые семейства |
| `smoke_B_data.json` | 16 слайдов: метрики, таблицы, контракт, все 3 чарт-семейства, таймлайн, оргсхема |
| `smoke_C_photo_gen.json` | 13 слайдов: фото-варианты + клон-ветки (метрики N=5 статгрид, прямой таймлайн N=6, таймлайн N=3 FILL) |
| `smoke_D_photoswap.json` | Photo-swap: hero, team (аватары), moodboard |
| `agenda_sections_deck.json` | Агенда per-section (active_index) |
| `linechart_deck.json` | Замена данных чартов (3 семейства) |
| `photo_swap_deck.json` | Photo-swap подробно: пул Я.Диска и свои файлы, center-crop |
| `columns_router_deck.json` | Развилка columns: био N=3 → FILL; явный variant — override; не заполнил донора — честная ошибка (плитки выпилены 0.21.0) |
| `takeaways_router_deck.json` | takeaways: развёрнутые N=3 → FILL #21; короткие/чужой N — честная ошибка (плитки выпилены 0.21.0) |
| `custom_html_deck.json` | Ветка custom (HTML-хэтч): матрица недель, нативная таблица, инфографика-глифы из `custom_slide.html`; нужны node+Chrome+uharfbuzz (preflight покажет) |
| `custom_recipes_deck.json` | Рецепты кастом-структур (`custom_recipes.html` + references/custom-recipes-eda.md): 2×2, водопад, гантт, воронка, оргсхема, статус-матрица; регрессия data-line (нативные линии/стрелки) и кругов border-radius:50% |
| `custom_chart_deck.json` | Нативные PowerPoint-чарты из custom (`custom_chart.html`, data-chart 0.35.0): column 2 серии + labels, line, doughnut с процентами; заглушка-потомок в .pptx не идёт; chart-парты + встроенные книги в пакете |

Вместе smoke A+B+C покрывают все семейства каталога — если что-то сломалось
после правки шаблона, эти три спека это покажут.

Ключ `"regression_smoke": true` в корне спеки — ТОЛЬКО для технических
смоуков этого реестра: ослабляет жёсткий гвард A12 (максимум один плиточный
GENERATE на дек, user-правило 2026-07-13) до предупреждения, потому что
смоуки прицельно гоняют плиточную ветку несколько раз. В боевых деках ключа
быть не должно.

## Известные ограничения (не баги — сообщать не нужно)

- **Таймлайн N≥7** — честная ошибка «дели на два слайда».
- **Слайд с чартом** (linechart/charts_compare/charts_duo) — не более 1 раза
  на дек каждый (ограничение PowerPoint на шаринг chart-партов).
- **Мини-чарты think-cell** (семейство impact #30) — заполняются только
  подписи, данные диаграмм остаются дизайнерскими (passthrough).
- **Заголовок чарт-слайда в 2 строки** → подзаголовок обязан быть пуст
  (машинный чек даст понятную ошибку).
- **Длинные слова**: описания прямого таймлайна — слова до ~12 букв;
  имена категорий BAR/COLUMN — короткие (узкие подписи оси переносятся).
- **Фото** — только пул «Нейро-фото Еда» (Я.Диск, качается сам) или свои
  файлы; со стоков не тянем. Портретные фото на полноэкранных подложках
  дают warning «мыло» — это сигнал взять фото крупнее.
- **PowerPoint-зомби**: если рендер стабильно падает с `-9074`/timeout —
  перезапустите PowerPoint руками, батчи рендеров его клинят.
- **⚠ ШАБЛОН ИЗМЕНИЛСЯ** в начале сборки — информационное: дизайнер правил
  шаблон; сборка продолжается. Ошибкой считается только падение якорей.
- **Дословный текст не резиновый**: канва дизайнерская и фиксированная —
  длинный готовый текст в маленький слот не поместится никогда, «подгони
  коробку под текст» скилл не делает принципиально. Штатное поведение
  с 0.2.0: агент примеряет весь дек и согласует проблемные места ОДНИМ
  fit-отчётом (меню вариантов — content-assembly-rules.md §2.2) — если вместо
  этого идёт пинг-понг по слайду, это баг.

## Формат багрепорта

Чтобы баг можно было воспроизвести, приложите:

1. **deckspec.json** (или промпт, который вы дали агенту);
2. **полный вывод сборки** (`build_deck.py` печатает решения роутера и гейт);
3. **рендер проблемного слайда** (PNG из `*.preview/`) или сам `.pptx`;
4. **что ожидали / что получили** — одной-двумя фразами;
5. **версию скилла** (`version:` во frontmatter SKILL.md) и дату/время —
   для сверки с ревизией шаблона: какая именно
   ревизия у вас, видно по md5-пину в `Templates/manifest.json`; дизайнер
   шаблон периодически обновляет, но движок всегда берёт запиненную ревизию.

Куда: тикетом в очередь Трекера
[VISCOMMSSKILLS](https://st.yandex-team.ru/VISCOMMSSKILLS). Быстрый путь —
скрипт: пункты 1–3 отдайте флагами, пункт 4 — `--expected`/`--got`, пункт 5
(версию, пин ревизии, платформу, дату) он соберёт из рабочей папки сам:

```bash
sh scripts/run.sh scripts/report_issue.py --summary "суть одной фразой" \
    --expected "..." --got "..." \
    --deckspec deckspec.json --log build.log --render slide_07.png \
    --template gor-services
```

Скрипт работает только локально: ничего не отправляет, не читает токены и
печатает MCP-ready поля вместе с абсолютными путями вложений. После явного
подтверждения пользователя агент создаёт тикет и прикладывает файлы через
Tracker MCP. Если Tracker MCP недоступен, в выводе есть ссылка `createTicket`
с заполненными полями для ручной отправки.
Баг — тип task + тег `bug` (дефолт); идея/доработка — `--kind improvement`.
Изменения в скилл вносит команда визуальных коммуникаций: ваш тикет
попадает в план и возвращается релизом с новой версией скилла.

## Что особенно интересно проверить

- Свой реальный контент (не демо): отчёты, питчи, обзоры — насколько план
  дека и выбор семейств попадают в ожидание.
- Разнообразие: агент не должен собирать каждый дек из одной и той же
  пятёрки семейств (правило раздела 0 deck-archetypes).
- Редполитику: заголовки-выводы, цифры с базой/периодом, финал = CTA
  (никогда «Спасибо»), пустой слот вместо текста «лишь бы заполнить».
- STOP-точки: агент обязан показать план до сборки и рендеры до финала.
- Бриф (новое в 0.2.0): цель и аудитория — отдельными вопросами; при
  внешнем выступлении или деке ≥15 слайдов агент обязан сам углубить бриф
  (кто в зале, что должны запомнить/сделать, тон) и предложить гипотезы
  ответов.
- Готовый дословный текст (новое в 0.2.0): дайте свой текст «положи как
  есть» — ожидания про фиксированную канву должны прозвучать ещё в брифе,
  переговоры о нехватке места прийти одним fit-отчётом, формулировки без
  согласия не меняться.
- Заметки спикера (новое в 0.2.0): попросите «полный текст — в заметки» —
  проверьте в PowerPoint панель заметок под слайдом.
- Свои изображения (новое в 0.4.0): дайте папку с картинками или черновик
  .pptx со скринами/фото — агент обязан спросить об источнике ещё в брифе,
  сделать опись, показать кандидатов и поставить их в фото-слоты; мыльные
  или крошечные картинки в слотах — баг.
- Перевёрстка (новое в 0.5.0): дайте ГОТОВЫЙ дек «причеши, контент не трогай» —
  агент обязан: проговорить ожидания (что сохранится 1:1, что изменит форму),
  показать послайдовое сопоставление ДО сборки, перенести тексты дословно,
  заметки спикера и картинки исходника, а нехватку места согласовать одним
  fit-отчётом. Ступор, пересочинение текстов или потеря картинок — баг.
