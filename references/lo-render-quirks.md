# Реестр расхождений LibreOffice-рендера с PowerPoint

LibreOffice — **скрининг-движок** визуальной самопроверки (quality-gates.md §4):
он позволяет пройти чеклист B2–B13 на любой ОС, но рендерит не пиксель-в-пиксель
как PowerPoint. Этот файл — реестр известных расхождений для НАШИХ шаблонов:
при LO-рендере классам из таблицы глаз не верит, а перепроверяет мерой.

Пользователю уровень рендера не сообщается никогда (правило 8 SKILL.md,
Rule 16 редполитики): гарантию корректности несут машинные гейты (они
калиброваны под PowerPoint и от движка рендера не зависят), LO-скрин — только
визуальный слой поверх них.

## Как пользоваться (агенту при LO-скрининге)

1. Прошёл B2–B13 по LO-рендеру как обычно.
2. По каждой строке таблицы со статусом «кандидат» или «подтверждено»:
   визуальному впечатлению не доверять — выполнить перепроверку из колонки
   «Чем перепроверять мерой».
3. Дефект, видимый ТОЛЬКО на LO-рендере и не подтверждённый мерой, — не дефект
   дека: не чинить контент под артефакт движка (запиши наблюдение владельцу
   скилла — кандидат в эту таблицу).

## Реестр

Статусы: **подтверждено** — воспроизведено на калибровке PP-vs-LO;
**кандидат** — типовое подозрение, на калибровке ещё не проверялось
(до проверки считать недоверенным = перепроверять мерой всегда).

| Класс | Как может врать LO | Чем перепроверять мерой | Статус |
|---|---|---|---|
| Шрифтовые метрики: переносы строк, ширина текста | другой шейпинг → лишний/пропавший перенос, другая ширина строки | lint по глифам + `containment` (калиброваны под PP — они и есть истина) | кандидат |
| Контейнмент текста в плашках (вертикаль) | глиф «вылезает»/«влезает» иначе, чем в PP | `fit.text_height_in` по слоту vs геометрия плашки из fill-map | кандидат |
| Нативные чарты: метки данных, подписи осей, легенда | своя раскладка меток → слипание/смещение, которых в PP нет | readback данных (`lib/charts.py`) + позиции меток в XML (`c:dLbl`) | кандидат |
| Фото: кроп/скругления подложек | другая интерпретация srcRect/радиусов | кроп-математика движка (`lib/images.py`) — center-crop считается нами, не рендером | кандидат |
| Прозрачности/градиенты дизайнерского декора | упрощение эффектов темы | passthrough-декор не трогаем движком → расхождение = артефакт LO, в PP верно | кандидат |
| Автополя мастера (номера страниц, `a:fld`) | показывает кэш или плейсхолдер | не трогаем по определению (common-mistakes.md) — на LO-рендере игнорировать | кандидат |

## Как пополнять (мейнтейнеру): калибровочная сессия PP-vs-LO

Разово на Маке с PowerPoint (повторять при смене мажорной версии LO/шаблона):

1. Собери 2–3 смоук-дека, покрывающих семейства (`examples/smoke_A/B/C/D`).
2. Отрендери каждый ДВАЖДЫ: PP и принудительно LO (убери PP из каскада —
   временно переименуй `/Applications/Microsoft PowerPoint.app` нельзя;
   проще: `soffice --headless --convert-to pdf` руками, как в render.py).
3. Сравни попарно по слайдам (глазом + `compare`/пиксель-дифф по желанию).
4. Каждое расхождение → строка таблицы: класс, как проявляется, чем
   перепроверять мерой; статус «подтверждено». Не воспроизвёлся кандидат —
   отметь «не воспроизводится (LO x.y, дата)» и сними недоверие.
5. Сообщи команде скилла (тикет в VISCOMMSSKILLS): подтверждённый класс
   вшивается в справочник, машинно-ловимый — становится чекером.
