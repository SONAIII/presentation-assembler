# Кастомные слайды: HTML-хэтч (family: custom)

Вторая ветка роутера: **fill → custom** (плиточная генерация выпилена 0.21.0;
клон-роутеры таймлайна/стат-сетки — часть fill-семейств). Для контента,
которому НЕТ готового семейства ([families-eda.md](families-eda.md)). Слайд верстается в HTML по грамматике дизайн-системы Еды,
обмеряется headless Chrome'ом и собирается **нативными редактируемыми шейпами**
на хроме дизайнерского лэйаута (заголовок — в TITLE-плейсхолдер, номер
страницы — от лэйаута). Деливерабл остаётся честным .pptx на теме шаблона.

## Когда включать (порядок строгий)

1. Сначала fill: семейство под контент есть → заполняй готовый слайд (клон-роутеры
   таймлайна/стат-сетки/columns — часть fill-семейств, не отдельная ступень).
2. Потом реворд: контент можно перекроить под готовое семейство (правило 16) →
   предложи это.
3. Потом custom. Типовые кейсы: матрицы/ганты, treemap, плотные
   композиции из карточек с числами, нестандартные сравнения, карточки со
   структурными атомами — бейджи + пилюли + подписи + лид-ины
   ([content-assembly-rules.md §1.0](content-assembly-rules.md); скелет —
   рецепт «бейдж-карточки»).
4. Custom недоступен (нет node или Chromium-браузера — проверь ЗАРАНЕЕ:
   `python3 $SKILL_DIR/scripts/preflight.py --custom-only`)? Плиточного
   фолбэка больше нет (0.21.0). Контент реально просит custom → ПРЕДЛОЖИ
   пользователю поставить headless-хромиум: `npx playwright install chromium`
   (~150 МБ, кэш пользователя, резолвер найдёт сам); ставить — ТОЛЬКО после
   явного «да» (скачивание из сети), после установки перепроверь
   `--custom-only`. Отказ / нет node / нет сети → реворди под готовое
   семейство, честно назвав упрощение. CHROME_PATH=<путь к Chrome/Chromium> —
   если браузер есть в нестандартном месте; Яндекс.Браузер не годится — его
   headless виснет (проверено 2026-07-23).

Кастом дороже и медленнее fill (обмер + конверсия на слайд) — сперва честно
ищи готовое семейство по всей карте.

Две типовые ловушки (кейс 2026-07-15):

- **HTML-источник контента ≠ повод для custom.** Контент пришёл готовым
  HTML-деком (перевёрстка, черновик) → роутер всё равно решает по СОДЕРЖАНИЮ
  слайда, не по формату источника: текстовые колонки из чужого HTML — это
  family columns, не «уже свёрстано, оставлю кастомом».
- **Текстовые колонки/карточки custom не берёт.** Слайд, чьё тело — 2–4
  однородные плашки с текстом (заголовок + тезисы), собирается семейством
  columns/takeaways; `blocks[].desc` принимает список абзацев,
  так что «в карточке несколько буллетов» — не причина для кастома, а реворд.
  Гвард A13 остановит такую сборку честной ошибкой.
  **Зеркальная граница (user-кейс 2026-07-16):** карточки СО СТРУКТУРНЫМИ
  АТОМАМИ — бейджи, пилюли, подписи, лид-ины
  ([content-assembly-rules.md §1.0](content-assembly-rules.md)) — это НЕ
  «однородные текстовые карточки»: их custom берёт законно, и A13 их
  пропускает (крупные не-текстовые атомы выводят слайд из эвристики).
  Утрамбовать такие карточки в columns, потеряв якоря, — ошибка
  той же тяжести, что лишний кастом: правило соответствия двустороннее.
- **Чистая таблица** (один `<table>` и ничего больше) — сперва посмотри
  семейство `datatable` (#36, дизайнерская таблица 9×4): размеры совпали →
  fill; не влезла — custom даст нативную таблицу (ниже).

## Как собрать слайд

Сначала проверь [custom-recipes-eda.md](custom-recipes-eda.md) — проверенные скелеты
типовых структур (2×2, водопад, гантт, воронка, оргсхема, статус-матрица,
бейдж-карточки, витрина скринов); есть подходящий — копируй его, не верстай
с нуля.

Дизайн-система для кастома живёт ВНУТРИ скилла: `$SKILL_DIR/assets/eda/deck.css`
(токены, роли текста, атомы — card, value-*, mark, table, grid, bar-row,
stat-row, badge, icon-chip и т.д.; читай сам CSS — атомы самоописаны в
комментариях; самодостаточность — в разделе «Зависимости и отказы» ниже).

1. **Файл**: один .html рядом с deckspec — ПОЛНЫЙ документ
   (`<!DOCTYPE html><html>…<body>…</body></html>`; фрагмент без обёртки
   обмерщик тоже переварит — зонд уйдёт в конец файла, — но канонический
   вид — полный документ), канва 1920×1080:
   `<div id="deck"> → <section class="slide slide--content">`.
   **Якоря лэйаута неподвижны** (user-правило 2026-07-20): заголовок (y=79),
   поля (x=125) и полоса низа — футер-плейсхолдер y 981→1015 плюс поле номера
   страницы x 1759→1797, y 994→1013 — датумы, ВНУТРИ которых строится вёрстка.
   Контракт `.slide--content`: `padding:79px 125px 120px` → контент заканчивается
   на y≤960, в полосу номера не заходит НИЧЕГО (ни плашки, ни текст, ни линии).
   Тесно — ужимай карточки/текст, а не отступ: наложение на якорь не
   маскируется и не «прикрывается» номером сверху. Зеркало `.pagenum` в HTML
   стоит в координатах реального поля номера (right:123px, bottom:67px, 18px) —
   в .pptx оно не конвертируется, номер даёт лэйаут.
   Стиль — одним из двух способов, оба без внешних скиллов:
   - **Линк на завендоренный CSS** (полная библиотека атомов, чистый HTML):
     `<link rel="stylesheet" href="file://$SKILL_DIR/assets/eda/deck.css">` —
     подставь реальный абсолютный путь скилла вместо `$SKILL_DIR` (тот же, что
     в командах `build_deck.py`).
   - **Инлайн-`<style>`** (самый переносимый, ноль внешних файлов) — как в
     `examples/custom_slide.html`: скопируй его как заготовку и наполни.
   Картинки/фото — тоже АБСОЛЮТНЫМИ `file://`-путями (обмерщик копирует HTML
   во временный файл, относительные пути поедут). Шрифты YS — системные,
   `@font-face` не нужен.
2. **deckspec**:
   ```json
   {"family": "custom", "html": "custom_market_map.html", "html_slide": 0}
   ```
   `html_slide` — индекс слайда в HTML-файле (0-based, дефолт 0); из одного
   файла можно брать несколько слайдов разными записями.

## Инфографика: стрелки, да/нет, дельты, донаты

Несложная инфографика в кастоме собирается ШТАТНО — из готовых глифов и
CSS-атомов, зеркалящих палитру атомов шаблона v14 (те же стрелки и иконки,
что дизайнер положил для нативной ветки).

- **Глифы** — `$SKILL_DIR/assets/eda/glyphs/*.svg` (каталог — в README рядом):
  вставляй СОДЕРЖИМОЕ файла инлайном в разметку (не `<img src>` и не CSS-фон —
  обмерщик видит только инлайн-`<svg>`). Глифы самодостаточны, размер задавай
  атрибутами width/height. Набор: `arrow-right/down` (стрелка ink — зеркало
  atom:arrow), `chevron-right` (флоу между карточками), `check-circle` /
  `cross-circle` (да/нет — зеркала atom:icon-check/-cross), `delta-up/down`
  (рост/падение), `donut` (прогресс; пересчёт дуги — комментарий в файле,
  цифру в центр клади HTML-текстом ПОВЕРХ svg, не `<text>` внутри).
- **CSS-атомы** (deck.css, блок «Инфографика»): `.flow` — лента процесса
  (карточки-шаги + глиф-стрелки в зазорах), `.verdict-row` — строка «иконка
  да/нет + текст», `.delta` (+`--ok`/`--no`) — значение с глифом дельты,
  `.divider-h` — линия-разделитель.
- **Нативные линии и стрелки** — `<div class="nline" data-line="arrow"
  style="width:…;height:3px">` конвертируется в РЕДАКТИРУЕМЫЙ коннектор
  (токены: `arrow` / `arrow-start` / `arrow-both` / `dashed`; толщина —
  короткая сторона, цвет — background; только горизонталь/вертикаль).
  Оси, мосты водопада, линии «сегодня» — этим; мелкие глифы в потоке
  текста — SVG выше. Круг/эллипс — `border-radius:50%`, тоже нативные.
- **Нативные графики `data-chart` (0.35.0)** — числовой ряд в custom
  собирается НАСТОЯЩИМ PowerPoint Chart со встроенной Excel-таблицей
  («Изменить данные» работает штатно):
  ```html
  <div class="nchart" style="width:820px;height:520px"
       data-chart='{"type":"column","categories":["Q1","Q2"],
                    "series":{"GMV, млн":[12,18]},"labels":true}'></div>
  ```
  Бокс элемента = рамка чарта. Типы: `column`, `column_stacked`, `bar`,
  `bar_stacked`, `line`, `line_markers`, `area`, `pie`, `doughnut` (pie и
  doughnut — одна серия долей).

  **Канон стиля — движок ставит САМ** (user-правило 2026-08-10, «фундамент
  всех шаблонов»; база сверена с 6 дизайнерскими чартами Еды, нулевая
  линия — эталон-слайд владельца): БЕЗ сетки на фоне, БЕЗ левой оси
  значений — цифры читаются с меток данных прямо на графике (метки
  ВКЛЮЧЕНЫ по умолчанию); ось категорий — подписи, БЕЗ тиков, и ВИДИМАЯ
  нулевая линия (тонкая, цветом accent3 темы — каждый шаблон даёт свой
  оттенок); у плотной линии (>9 точек) подписываются только КЛЮЧЕВЫЕ
  точки — первая, последняя, минимум, максимум. Ничего из этого в спеке
  писать не нужно.

  Опции поверх канона: `"labels": false` — заглушить все метки,
  `"labels": "all"` — все точки плотной линии; на КОНКРЕТНОЙ серии
  `{"values": [...], "labels": false}` — серия-контекст без цифр (паттерн
  дизайнера: главная серия с цифрами, фоновая — без); `"axis": true` —
  осознанно вернуть ось значений (плотный документ-режим);
  `number_format` (напр. `"0\"%\""`); `legend` (дефолт: серий >1 или
  pie/doughnut); `title` (обычно НЕ нужен — вывод живёт в заголовке слайда,
  Rule 2). Цвета серий — от темы шаблона (accent-ряд дизайнера), точечно —
  `"color"` на серии (см. «Чартовые приёмы»); шрифт — бренда; серий ≤3
  (канон §4 chart-selection). Потомки элемента — заглушка
  для браузерного превью такта-1, в .pptx не идут. Комбо «столбцы + линия»
  одним чартом не строится — два `data-chart` рядом. ПОРЯДОК ПРЕЖНИЙ
  (fill-first): сперва chart-донор семейства ([chart-selection.md](chart-selection.md) §2, §5 —
  дизайнерский стиль), `data-chart` — когда донора нет/занят/форма другая
  (stacked, area, doughnut, второй график в деке).

  **Чартовые приёмы** (проверены боевым переносом 2026-08-10 — НЕ выясняй
  их заново пробными сборками, они уже работают так):
  - **Линия цели / бенчмарк** — ещё одна line-серия с постоянным значением
    на тех же категориях: `{"values": [65,65,…], "color": "#C9C6C3",
    "labels": false}` — серая, без повторяющихся цифр; число — в имя серии
    («цель 65%»), оно читается в легенде и дублируется в подзаголовке.
  - **Плотный ряд** (понедельные точки, 30+ категорий): метки ДАННЫХ движок
    проредит сам (ключевые точки, см. канон). Подписи ОСИ категорий:
    каждую не нужно — категории-«пробелы» разной длины (`" "`, `"  "`)
    дают ось без подписей, повтор подписи периода («янв», «янв», «фев»…) —
    разреженные метки. Пустые строки `""` не использовать.
  - **Пропуски в данных — `null`**: точка пропускается (линия рвётся) —
    честный способ показать неполный ряд; ряд им не «дорисовывается».
  - **Цвет серии**: дефолт — accent-ряд ТЕМЫ шаблона по порядку серий;
    точечный override — значение серии объектом:
    `"цель 700": {"values": [700,700,…], "color": "#C9C6C3"}` (line —
    линия и маркеры, column/bar/area — заливка; hex из ПАЛИТРЫ шаблона,
    не выдумывай цветов). Для pie/doughnut цвет серии смысла не имеет —
    доли красит тема. Серию-пустышку для сдвига цвета НЕ делать
    (устаревший хак до 0.37.0: мусорная строка в «Изменить данные»).
  - **Данные уже проверены машиной**: движок делает readback вставленного
    чарта (категории/серии/значения читаются назад), parity-гейт сверяет
    тексты — НЕ распаковывай .pptx и не читай XML чартов руками, это
    потерянные минуты сборки.
  - **Декоративные фоновые серии исходника** (полупрозрачные столбики без
    значений) в перенос не тянутся пиксельно: их факт — текстом карточки,
    отступление — списком в сдаче (restyle-mode.md, «честные ожидания»).
- **Редполитика.** Стрелки, шевроны, линии — ink или серые, НЕ жёлтые
  (жёлтый — одна роль на слайд, стрелкам её не отдаём). Зелёный `--ok` и
  красный `--no` — санкционированное исключение палитры ТОЛЬКО для семантики
  (да/нет, рост/падение), не для декора и не «оживить слайд». Донат — жёлтая
  дуга на сером треке, не больше одного акцентного на слайд.
- **Границы.** Глиф конвертируется растеризацией (×4, прозрачный фон) — в
  PowerPoint он не редактируется; для мелких значков это ок. Если слайд
  целиком — флоу/процесс из однотипных карточек и паттерн повторяется из
  дека в дек, это кандидат в генеративную структуру (в палитре уже лежат
  нативные atom:arrow/divider/icon-* — см. «Воронку продвижения» ниже).

## Требования конвертируемости (жёсткие — иначе слайд соберётся с потерями)

- **Декор только реальными элементами.** CSS `::before`/`::after` обмерщику
  невидимы: точки легенд, вуали — тегами. Вуаль на фото —
  `<div>` с `background: linear-gradient(...)` внутри фото-рамки.
- **Списки — настоящими `<ul>/<li>` (и `<ol>` для нумерации).** Конвертер
  собирает их НАТИВНЫМИ абзацами-буллитами PowerPoint (маркер «•» 150%
  цветом текста, висячая строка 36.9pt; `<ol>` — автонумерация с
  продолжением между пунктами). Канон маркера снят с донора Хурала #42 и
  действует движковым ДЕФОЛТОМ для всех шаблонов, пока дизайнер бренда не
  принесёт свой. Литеральные дефисы/точки вместо маркеров НЕ верстать —
  дизайнер бракует «буллиты отдельной текстовой коробкой с дефис», когда
  рядом на донорах буллиты настоящие (хэндофф Ultima 2026-08-11, O2).
- **Правило точек действует и в кастоме (0.40.1).** Самостоятельный абзац
  не заканчивается точкой: движок срезает финальную точку КАЖДОГО абзаца
  при конверсии (тексты тела, ячейки таблиц, заголовок) — зеркало
  typo-прохода fill-пути (content-assembly-rules «Финальная точка»); «…»
  и внутренние точки живут. NBSP-часть typo к кастому сознательно не
  применяется: замена пробелов сдвинула бы точки переноса против обмера.
- **SVG самодостаточные**: fill/stroke атрибутами в разметке, не наследованием
  CSS извне. Иконки растеризуются (×4, прозрачный фон) и ложатся picture'ами.
- **Фото**: `<img>` с `object-fit: cover` внутри рамки с `overflow: hidden` —
  движок повторит кроп нативным srcRect (пиксельная сверка спайком). Другие
  object-fit не поддержаны.
- **Текст не впритык** к границе контейнера: PowerPoint не применяет
  GPOS-кернинг и набирает до ~0.8% шире браузера. Запас движок добавляет сам,
  но слово, влезающее в последний пиксель, — риск лишнего переноса.
- **Один `.h1`**; плашки `.mark` в заголовке — только на первой строке
  (глубже — предупреждение при сборке, проверяй глазом).
- **Роли элементов `data-ppt-role`** (0.34.0, для переноса готового HTML,
  где классы не по грамматике deck.css): `title` — текст уходит в
  TITLE-плейсхолдер наравне с `.h1`; `body` — «это НЕ заголовок» (снимает
  подозрение A16 у крупного текста); `eyebrow` — надзаголовок/трекер, обычный
  текст тела (с заголовком НЕ конкурирует: заголовок выбирается только по
  `.h1`/`role=title`, не по позиции); `decor` на `<svg>` — осознанный декор
  без данных (снимает гейт A17). Роль — override, грамматика классов остаётся
  основной. Гейт A16: слайд БЕЗ заголовка, но с крупным буквенным текстом
  (≥48px, ≥8 букв) в верхней четверти канвы — сборка падает с рецептом:
  такой текст почти наверняка заголовок, и без плейсхолдера дизайнер не
  отредактирует его штатным полем PowerPoint.
- **Числовые ряды — НЕ в SVG.** График, свёрстанный SVG-картинкой,
  растеризуется и не редактируется через «Изменить данные» — гейт A17 валит
  сборку по SVG с ≥3 числовыми подписями (`<text>`/`<tspan>`). Числовым
  рядам — chart-донор семейства ([chart-selection.md](chart-selection.md) §2,
  §5) или таблица `datatable`; глифы-декор без данных — `data-ppt-role="decor"`.
- **Фон слайда — из палитры хрома** (правила by_bg профиля: у Еды
  белый/серый/жёлтый). Фон вне палитры больше не теряется: движок переносит
  его нативно — фоном слайда p:bg (лежит под хромом, номер страницы виден),
  а если лэйаут несёт собственный фоновый прямоугольник (Еда) — фигурой-фоном
  под контентом (номер/футер лэйаута уходят под фон, как под фото-панелью
  канона) — и громко предупреждает: хром лэйаута (цвет заголовка, номера) на
  такой фон не рассчитан, читаемость сверяй на PP-рендере. Канонный путь —
  фоны палитры.
- **Таблицы — только настоящим `<table>`** (семантическая разметка
  th/td, стиль `.table` или свой): конвертер собирает из него НАТИВНУЮ
  редактируемую таблицу PowerPoint (a:tbl) — ширины колонок, высоты строк,
  границы по сторонам ячеек, заливки, выравнивания, rowspan/colspan из
  вёрстки. Выравнивание — по правилу вёрстки (user 2026-07-20): текстовые
  колонки влево (дефолт `.table`), числовым колонкам ставь класс `.num`
  на th+td (вправо, заголовок — как колонка); линт проверит готовый a:tbl
  тем же правилом (`table-align`). Табличная сетка из div'ов нативной таблицей НЕ станет (соберётся
  текстбоксами) — не верстай таблицы гридами. Ограничения: фон задавай на
  ячейках (фон самого `<table>` не переносится); плашки-бейджи внутри ячеек
  (chip/mark с собственным фоном) лягут оверлеями ПОВЕРХ таблицы, их текст
  в ячейку не попадает — при редактировании таблицы такой бейдж двигается
  отдельно.
- Текст всегда ложится ПОВЕРХ фигур (текст под полупрозрачной плашкой
  не выйдет).

## Вёрстка в полях и плашках (жёсткие гварды, 0.32.2 — урок дека drive-long)

Мотив: первый дизайнер-тест Хурала — на custom-слайдах цифра порвала карточку
и слиплась с соседней, пилюли-статусы легли на заголовки, заголовок-колонка
переносился по слогам. Теперь это ЛОВИТСЯ ДВИЖКОМ, слайд не соберётся:

- **Шрифтовая проба (автоматическая).** Конвертер сверяет браузерный обмер
  каждого семейства с PP-метрикой (uharfbuzz): расхождение медианы >6% =
  браузер не видит шрифтов бренда и мерил подменным — вся геометрия
  недостоверна. Сборка падает с рецептом (`fetch_template.py --fonts`).
  Не обходить и не «подгонять» — чинить шрифты.
- **Поля канвы.** Контент живёт в полях профиля (`margins` в
  custom-profile.json; у Хурала Райдтеха 54px лево/право, 40px верх, 120px
  низ). Атом за полями = ошибка A15. Сетку распределяй ВНУТРИ полей — от
  поля до поля, а не от кромки канвы.
- **Вертикаль: контент ПРИЖАТ к нижнему полю** (хэндофф Ultima 2026-08-11,
  O1 — «плашки подняты сильно от нижней границы» на трёх кастом-слайдах).
  Правило про поля работает в обе оси: по горизонтали сетка тянется от поля
  до поля, по вертикали блок контента ЗАКАНЧИВАЕТСЯ у нижнего поля (у Хурала
  низ ≈ y 960, не выше y 900) — свободное место уходит МЕЖДУ заголовком и
  блоком, а не под блок. Дизайнерские доноры доводят чернила до поля и ниже
  (94–100% высоты); кастом, кончающийся на 75–85%, визуально «всплывает».
  Гвард A18 валит сборку при пустой полосе снизу больше 8% контентной
  высоты; вместе с A15 (выход ЗА поле) он держит низ в коридоре у поля.
- **Текст — внутри своей плашки.** Значение/лейбл не может быть шире
  карточки или пилюли (линт: `containment:text-outside-card/-pill`, HIGH).
  Пилюли-статусы верстай В ПОТОК (inline-flex: паддинг сам задаёт ширину
  пилюли под текст), НИКОГДА не absolute поверх текстовой строки — наезд
  пилюли на чужой текст тоже HIGH (`collision:pill-over-text`).
- **Кегль значений — считай до вёрстки.** 3 колонки → значение ≤115px;
  4 колонки → ≤88px; длинное число («22,400») при 4 колонках → 72px или
  сокращай формат (22.4K). Число шире карточки не бывает «норм».
- **Узкая колонка заголовка.** Самое длинное слово обязано влезать в ширину
  колонки на выбранном кегле — иначе PowerPoint порвёт слово по слогам
  («bette-/r fleet»). Не влезает — кегль ниже или колонка шире.
- **Красный гейт = дека НЕТ.** При HIGH-находках файл переименовывается в
  `*.REJECTED.pptx` — рабочего артефакта не существует; чини и пересобирай,
  отдавать REJECTED нельзя (SKILL.md §5).

## Что произойдёт при сборке

Фон HTML-слайда выбирает лэйаут хрома (белый → Title_no frame, серый →
Title_grey, жёлтый → Yellow_no frame). Заголовок вливается в дизайнерский
плейсхолдер (типографика — дизайнера), тело — шейпы/текстбоксы/фото по обмеру,
`<table>` — нативные редактируемые таблицы.
Причина решения печатается в плане сборки (`[HTML-хэтч: файл[N]]`).

Особенность: на слайдах с фото-панелью до правого края номер страницы уходит
под фото (плейсхолдер лэйаута всегда под шейпами) — как и в дизайнерских
слайдах с полноразмерным фото; не дефект. Это ЕДИНСТВЕННОЕ санкционированное
исключение гварда A15 (фото-панель канона: от верхнего инсета до нижней
кромки); контентные атомы в полосу номера не пускаются никогда.

## Гейты

**Такт-1 превью (2026-07-16, SKILL.md шаг 3.7):** свёрстанный кастом-слайд
показывается пользователю ДО сборки дека — скриншот тем же Chrome, что
меряет конвейер:

```bash
python3 $SKILL_DIR/scripts/html_preview.py slide.html -s 0 -o /private/tmp/preview.png
```

Правка макета на этом такте стоит один HTML-файл, а не пересборку и
переприёмку всего дека. Шаблонные слайды на такте-1 не имитируются —
их пользователь видит в рендерах собранного .pptx (STOP шага 4).

Дальше — crash + lint автоматически при сборке (как для всех слайдов),
плюс гварды по обмеру: A15 (фидбек-репорт 2026-07-20 «карточки накрыли номер
страницы, гейт молчал») — атом тела за канвой 1920×1080 или в полосе
футера/номера выбранного лэйаута; A16 — заголовок мимо TITLE-плейсхолдера;
A17 — график SVG-картинкой (см. «Требования конвертируемости»); A18 —
контент «всплыл» над нижним полем (см. «Вёрстка в полях и плашках»,
вертикаль). С 0.34.0
гварды A13/A15/A16/A17/A18 собирают нарушения по ВСЕМ слайдам дека и падают
ОДНИМ списком — чини всё разом, не по одной находке за пересборку (в смоуках
с `regression_smoke` ослабляются до ⚠);
composition-check к custom не применяется — вёрстку посчитал браузер.
Рендер + самопроверка B2–B13 обязательны как обычно (quality-gates.md §4);
глазом сверь слайд с HTML-оригиналом в браузере — это твой эталон.

## Зависимости и отказы

Всё нужное — В ПАПКЕ СКИЛЛА (CSS `assets/eda/deck.css`, обмерщик `scripts/html_measure.mjs`, конвертер `lib/html2pptx.py`); других скиллов НЕ
требуется — НЕ ищи и НЕ подключай сиблинг-скилл, папка самодостаточна. Из
ОКРУЖЕНИЯ (как и для остального скилла — python-pptx, шрифты) нужны: node,
Chrome/Chromium, `uharfbuzz` (pip), шрифты YS (`fetch_template.py --fonts`);
это машинные инструменты, preflight их проверяет. Чего-то нет → сборка упадёт
честной ошибкой с подсказкой; НЕ собирай кастом «на глаз» без обмера.

## Воронка продвижения

Один и тот же кастом-паттерн повторяется из дека в дек → это кандидат
в генеративную структуру `structures/` — скажи владельцу скилла (не строй
структуру сам под конкретный дек, жёсткое правило 1).
