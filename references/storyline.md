# Storyline: сюжет дека до плана слайдов

Этот файл читается **на шаге 2 SKILL.md, ДО планирования слайдов**. Порядок:
бриф (цель, аудитория, подача) → storyline-конструкция (этот файл) → план
слайдов (архетипы + семейства). Слайдовый уровень тех же принципов —
[editorial-principles.md](editorial-principles.md) (Rules 1, 2, 2a, 4);
здесь — уровень дека целиком: сюжет, из которого слайды рождаются.

Наш скилл закрывает ВСЕ типы дек сам — от плотного финансового отчёта до
доклада со сцены. Никаких отсылок к другим скиллам; разница режимов — внутри
этого файла (раздел 0).

---

## 0. Развилка подачи — из брифа (шаг 1, вопрос 5)

Как дек будет жить, определяет плотность и драматургию. Три режима:

**Документ (reading deck).** Дек читают без спикера: отчёты, финансы,
консалтинговые материалы, стратегии на согласование, рассылка по почте.
Это дефолт для большинства наших пользователей (стратегия, финансовые
департаменты, консалтинговый контент).

- **Плотность — фича, не бага.** Плотные таблицы, подробные подписи, полные
  ряды данных — норма. НЕ урезай контент ради «воздуха» и «одна мысль — один
  слайд» в ущерб полноте: плотный контент кладётся в вместительные формы
  (`datatable`, `compare`, `gantt`, `text_grid`, `mixed`, custom-HTML).
  Сокращения дословного текста — только через fit-отчёт
  ([content-assembly-rules.md §2.2](content-assembly-rules.md)).
- **Самодостаточность — ядро** (Rule 13): читатель без спикера должен
  восстановить вывод по заголовкам и понять каждую цифру по подписям.
- **Драматургия = логика аргумента, не драма.** Никаких hook-слайдов,
  «поворотов» и театральности — только answer-first, опоры, факты.

**Выступление (presentation deck).** Спикер + экран: слайд — опора речи,
не документ.

- **Разреженность:** одна мысль на слайд, крупные цифры, минимум текста.
  Полные формулировки — в `"notes"` (заметки спикера), не на канве.
- **Драматургия включается** — раздел 4.

**Гибрид (показ + рассылка).** Канва как для выступления, полнота как для
документа: полный текст в notes; детальные данные — appendix-слайдами после
финала (в основной части не мешают ритму, в рассылке читаются).

Режим не назван в брифе → выведи из цели и аудитории, зафиксируй в плане
как факт (Rule 16 — не переспрашивай, пользователь поправит на STOP).

## 1. Storyline-конструкция — обязательна в любом режиме

До плана слайдов сформулируй (и покажи пользователю на STOP шага 2 —
это контент-ризонинг, не внутренняя кухня):

1. **Главный вывод** — одна фраза ≤140 знаков с «so what» для этой аудитории.
   Тест: аудитория закрыла дек после второго слайда — что унесла? Не
   формулируется одной фразой — либо мыслей две (дели дек), либо мысль не
   созрела (вернись к брифу).
2. **SCQA-логика открытия** — Situation (положение, с которым аудитория
   согласна) → Complication (что изменилось / болит) → Question → Answer
   (= главный вывод). Это скелет exec summary (Rule 4) и первых слайдов:
   читатель за минуту понимает, с чем пришли и что утверждаем.
3. **Опоры** — 3 (реже 2–4) причины/аргумента под главный вывод. MECE:
   не пересекаются, вместе закрывают вывод без дыр. Каждая опора закрыта
   фактом по Rules 6–8 (число + единица + период + база). Опора без факта →
   найти данные, пометить «гипотеза, проверим к {дата}» или выкинуть.
   Опора-самооценка («команда молодец»), опора-процесс («провели работу»)
   и опора-план («будем делать X») — не опоры.
4. **Закрытие под цель из брифа:**
   - цель = решение/ресурс → финал «просим {решение} к {дата}, цена вопроса
     {X}» (CTA, Rule 2a);
   - цель = знание/алайнмент → финал «что запомнить»: 3 мысли-синтеза
     (раздел 3), не повтор заголовков;
   - цель = действие аудитории → конкретный next step с владельцем и датой;
   - целевого действия нет → финальный слайд не нужен, дек закрывает
     последний content-слайд (Rule 2a).

Каждый слайд плана обязан работать на главный вывод или закрытие. Слайд,
который «для полноты картины», — кандидат на вылет (Rule 12).

## 2. Склейка заголовков (horizontal logic)

После плана прочитай все action-заголовки подряд, сверху вниз. Должен
получиться связный рассказ на 30 секунд — сжатая версия дека. Получилось
оглавление («Контекст. Метрики. Команда. Планы») — переделывай заголовки,
не контент (Rule 2). Прогони по каждому «и что?» — ответ должен выводиться
из самого заголовка.

Это самый дешёвый тест качества storyline: одна минута, ловит и дыры в
логике, и label-заголовки, и лишние слайды (заголовок не встраивается в
рассказ → слайд под вопросом).

## 3. Жёсткость драматургии — по типу дека

Не дави один канон на всё: натянутый «поворот» в квартальном отчёте и
театральный hook в финансовой сверке читаются как фальшь и убивают доверие.

| Тип дека (архетипы — [deck-archetypes.md](deck-archetypes.md)) | Обязательно | Запрещено |
|---|---|---|
| **Решенческий / питч** (бюджет, согласование, инвест) | Вывод и запрос — в первую минуту (exec summary, слайд 2); финал = конкретный ASK с ценой и сроком | Прятать запрос в конец; «просим поддержки» без цифры |
| **Отчёт / статус** (квартальный, проектный, финансовый) | Вывод периода вперёд; честные факты, включая провалы (Rule 11) | Выдуманный «поворот», нагнетание драмы, натянутый hook |
| **Обзор / аналитика** (рынок, ландшафт) | Exec summary с выводами (не агендой); линейная структура допустима | Раздувать до «истории», где её нет |
| **Выступленческий** (хурал, публичный доклад, демо) | Полная драматургия — раздел 4 | Плотные таблицы на экране; «Спасибо. Вопросы?» |

Микс целей («и отчёт, и запрос ресурсов, и обучение») — выбери главную,
остальное в appendix или отдельный дек.

**Синтез «3 мысли» для закрытия** (цель = знание): каждая — законченное
предложение с глаголом и, где есть, числом; синтез поверх заголовков, не
их копипаста; самодостаточна (понятна без дека). «Команда. Метрики.
Планы.» — провал; «Конверсия +12 п.п., самый дешёвый рычаг — онбординг» —
работает.

## 4. Выступление: драматургия (только режимы «выступление» и «гибрид»)

- **Открытие — самый сильный факт, не «содержание».** Вытащи из материала
  наибольшую boldness: цифру, которая удивляет/болит/гордит; вопрос, который
  аудитория сама себе задаёт; конкретный случай; контраст («думали X —
  оказалось Y»). НЕ открытие: «сегодня я расскажу о…», биография спикера,
  агенда, благодарности. Если в материале есть реальный поворот (гипотеза
  не подтвердилась, причина не там) — не спойлери развязку в открытии:
  «потеряли 40% — и причина оказалась не там, где искали».
- **Answer-first не отменяется:** после открытия главный вывод звучит в
  первые 1–2 минуты, а не в финале.
- **Ритм:** после 3–4 плотных content-слайдов — смена темпа (`divider`,
  `statement`, `hero`, фото-слайд). Монотонная лента однотипных слайдов =
  аудитория в телефоне (стыкуется с правилом разнообразия семейств шага 2).
- **Финал = CTA** (Rule 2a), «Спасибо за внимание» запрещено. Длинному
  деку перед CTA — «Что запомнить» (3 мысли, раздел 3).
- **Полный устный текст — в notes**, канва несёт тезис.

---

## 5. Тесты storyline — прогнать перед STOP шага 2

1. **Вывод-тест:** главный вывод — одна фраза ≤140 знаков с so-what?
2. **MECE-тест:** опоры не пересекаются и вместе закрывают вывод? Под каждой
   — факт?
3. **Склейка:** заголовки подряд = связный рассказ?
4. **Закрытие-тест:** что аудитория решит/сделает/запомнит после дека?
   Ответ «ничего» = закрытие провалено.
5. **Жанр-тест:** жёсткость соответствует типу дека — нет натянутой драмы
   в отчёте, нет закопанного запроса в решенческом?
6. **Плотность-тест:** режим подачи учтён — документ не выхолощен ради
   «воздуха», выступление не перегружено таблицами?
