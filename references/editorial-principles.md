# Editorial principles: what the slide says, not how it looks

Актуальные правила и исключения: [content-challenge.md](content-challenge.md) и
[editorial-quick-ref.md](editorial-quick-ref.md). Они имеют приоритет над
категоричными формулировками исторического справочника ниже: сохраняй
согласованные тематические заголовки, не требуй CTA у информационного апдейта,
не навязывай обложку и exec summary короткому деку.

This file is about **content quality** — what goes on the slide before any layout decision. Layout rules live in [content-assembly-rules.md](content-assembly-rules.md); бренд и типографика живут в fill-maps шаблона и [quality-gates.md](quality-gates.md). This file is read **на шаге 2 (план дека) и шаге 3.5 (контент-вычитка) [SKILL.md](../SKILL.md)** — before writing any slide content, and again before finalizing copy.

A deck that follows brand rules but ignores these principles looks branded but reads as noise. A deck that follows these principles even with imperfect layout still lands the message.

> Mostly distilled from BCG / McKinsey storytelling conventions; написаны для Городских, применимы к любому шаблону Яндекса. The rules below are non-negotiable — if a rule conflicts with a designer slide's default, the rule wins.

---

## Rule 1 — Conclusion first, details second

State the answer up front. Details support it after. This applies to the deck as a whole (exec summary on slide 2), to each slide (action title = takeaway), and to each block of body text (lead sentence = point).

It is **absolutely fine** to lead with an unpleasant conclusion: «Улучшения ключевой метрики пока нет — ждём в Q3 за счёт X и Y». The reader respects directness; burying the bad news under three slides of context only delays the same reaction and costs trust.

| BAD (details → conclusion) | GOOD (conclusion → details) |
|---|---|
| «В апреле запустили A/B, в мае собрали данные, в июне валидировали — рост не подтвердился» | «Рост не подтвердился. A/B → данные → валидация в апреле–июне» |
| «Команда B усилилась 3 наймами, B2 закрыл 4 роли, всего 7 закрытий из 9 плановых» | «Закрыли 7 из 9 плановых ролей — 2 в подвешенном состоянии до Q3» |
| «Бюджет распределили на 4 направления с учётом приоритетов: X — 40%, Y — 30%…» | «80% бюджета идёт в X+Y. Остальное — в Z и W» |

**STOP signals.** Halt and rewrite if:
- The slide's main point only появляется в последнем буллете / последнем абзаце.
- Заголовок описывает тему, а вывод — в подписи под графиком.
- Чтобы понять смысл слайда, нужно прочитать его сверху донизу.

## Rule 2 — Action title: the slide's title IS the takeaway

A content slide's title is a **complete sentence** with subject, verb, and "so what". A reader who scans only the titles must reconstruct the deck's story. If the titles read like a table of contents, the deck has failed.

This is the highest-leverage rule in the deck. The title is the most visible line on every slide — wasting it on a category name throws away the highest-attention real estate.

| Topic title (BAD) | Action title (GOOD) |
|---|---|
| «Обзор рынка» | «Российский DOOH вырос на 47% YoY, драйвер — регионы» |
| «Итоги Q1» | «Q1 закрыли с превышением плана на 12%, digital +23%» |
| «Сегментация пользователей» | «3 сегмента дают 80% маржи, mid-market недонастроен» |
| «Ключевые направления» | «Концентрируем ресурсы на 3 направлениях из 7» |
| «Команда» | «Усилили команду 4 наймами в Q2, закрыли все ключевые роли» |
| «Риски» | «2 риска требуют внимания CEO в ближайший месяц» |

### What a good action title does

1. **States the answer.** Reader can stop after the title and know the point.
2. **Quantifies when possible.** «Выросли» — weak. «Выросли на 47%» — strong.
3. **Names the cause when the data shows one.** «Выросли на 47% YoY, драйвер — регионы».
4. **Frames the so-what for the audience.** Q2 report for board: «Q2 закрыли с превышением на 12%». Same data for the team: «Q2 показал, что digital готов масштабироваться».

### Where this rule applies

| Slide type | Action title required? |
|---|---|
| Контент-семейства: metrics, two_values, hero, columns, takeaways, steps, timeline, чарты (linechart/compare/duo), таблицы (datatable/compare/gantt), funnel, impact, grouped, mixed, text_grid, images, team | **Yes — always** |
| Генеративные плитки (reasons) и прямой таймлайн | **Yes** |
| `cover` | **No** — cover titles are deck names, not takeaways |
| `bodytext` (крупный тезис 110pt; Еда: `bodytext.json`) | **No** — тезис сам и есть манифест-заголовок |
| `closing` (CTA) | **No** — CTA is a call-to-action, not a takeaway (see Rule 2a) |
| `divider`, `toc`, `contacts` | **No** — служебные/секционные, фиксированный паттерн |

## Rule 2a — Финальный слайд = CTA, никогда «Спасибо»

«Спасибо. Вопросы?» как финал дека — муветон. Слайд сообщает «всё, шоу закончилось» и не оставляет аудитории никакого следующего шага. Аудитория уходит с ощущением окончания, а не с импульсом действовать.

В большинстве дек финальный слайд **вообще не нужен** — последний content-слайд с action-title уже завершает аргумент. Закрывающий слайд добавляй только если у аудитории есть конкретный следующий шаг.

Если деку нужен финал — это **CTA-слайд** (call-to-action):

| Контекст | CTA-формулировка |
|---|---|
| Питч / отчёт партнёрам / IR | «Контакты» + email/телефон / «Готовы обсуждать» + контакт |
| Стратегия / vision | «Давайте начнём» / «Что дальше» (с конкретным первым шагом) |
| Хурал / annual review | «Что запомнить» (повтор exec summary в 3–5 буллетах) или конкретный next step команды |
| Event-deck / public talk | «Зарегистрируйтесь» / «Подробнее на сайте {url}» / «Скачайте материалы» |
| Внутренняя задача / запрос ресурсов | «Нужны от вас: {решение / бюджет / ресурс} к {дата}» |

Используй семейство `closing` (вариант thanks_cta): слот `title` = твой CTA; дефолта вроде «Спасибо» нет.

**STOP signals.** Halt and rewrite if:
- Финальный слайд называется «Спасибо», «Вопросы?», «Спасибо за внимание», «Q&A», «Thank you» — переписать на CTA или вообще убрать.
- CTA-слайд не содержит конкретного следующего шага (просто «Контакты» без email, просто «Что дальше» без даты) — это замаскированный «Спасибо», переписать.

### Formatting

- **Max 2 lines** при дизайнерском кегле заголовка (лимиты слота меряются глифами при сборке). If your action title spills to 3 lines, the message is too long — shorten or split.
- **One sentence.** Two sentences in a title means the slide is doing two jobs — split.
- **No trailing period.** A title isn't punctuated like prose.
- **Avoid the colon.** «Q1: главное» reads as a label. Prefer «Главное в Q1 — …» or embed the verb directly.
- **Numbers as digits.** «3 сегмента», not «три сегмента».

**STOP signals.** Halt and rewrite if:
- Title is a noun phrase without a verb («Итоги Q1», «Обзор рынка»).
- Title needs the body to be understood («Результаты», «Динамика», «Выводы»).
- Two takeaways crammed into one title → split the slide.
- Title overpromises and the body underdelivers — fix one of them.

## Rule 3 — Simple language, short sentences

The audience reads the slide once, often peripherally while listening. Long sentences with subordinate clauses are not understood — they are skipped.

- **Max ~15 words per sentence on slides.** Hard ceiling 20.
- **Default: 1 thought = 1 sentence.** If you need «и», «а также», «при этом» three times in one sentence — split.
- **No jargon without expansion on first use.** «КАИ» on first use → «КАИ (корпоративный аналитический инструмент)». Then just «КАИ».
- **No bureaucratic phrasing.** «Осуществляем мониторинг» → «следим». «Произвели запуск» → «запустили». «В рамках реализации задачи» → cut entirely.

| BAD | GOOD |
|---|---|
| «В рамках реализации стратегии мы осуществили запуск нового сервиса для агрегации обращений» | «Запустили сервис, который собирает обращения в одном месте» |
| «Произведённые мероприятия позволили достичь увеличения показателя на 12% относительно базового периода» | «Показатель вырос на 12% к Q1» |
| «Несмотря на то, что данные находятся в процессе верификации, можно с осторожностью говорить о положительной динамике» | «Данные ещё проверяем — пока выглядит как рост» |

**STOP signals.**
- В предложении больше одной запятой ради подчинённого оборота — переписать.
- Появилось «осуществляем», «производим», «реализуем», «в рамках», «в части», «по итогам проведения» — переписать.
- Аудитория из 1С / финансов / юристов? Это исключение, не повод писать так везде.

## Rule 4 — Exec summary on slide 2 (decks ≥ 5 slides)

After the cover, slide 2 is an exec summary: **3–5 bullets that the audience must walk away with**. If they only see this slide, they should still know the answer.

The exec summary is not the agenda («Сначала расскажу про X, потом про Y»). It's the **conclusions** of the deck в сжатом виде, written before the body is written.

- **For decks 5–10 slides:** 3 bullets, each a one-line conclusion.
- **For decks 11–25 slides:** 5 bullets, organized по разделам.
- **For decks 1–4 slides:** Не нужен. Сама колода — exec summary.
- **For хурал / annual review:** Exec summary дублируется в конце как «Что запомнить».

| BAD (agenda) | GOOD (conclusions) |
|---|---|
| «Сегодня обсудим: 1) рынок, 2) продукт, 3) команду, 4) планы» | «Рынок DOOH +47% YoY • Продукт догнал план по DAU • Команда закрыта на Q3 • Просим $2M на масштабирование» |
| «Программа: итоги Q2, разбор метрик, риски, план Q3» | «Q2 +12% к плану • 2 метрики просели — фиксим в июле • 3 риска требуют решения CEO • План Q3 — фокус на retention» |

**STOP signals.**
- Слайд 2 — это «Содержание» / «Agenda» / «План доклада» → переписать в выводы.
- Не можешь сформулировать exec summary в 3 буллета — не понимаешь свой дек.

## Rule 5 — One idea per slide; series with a progress indicator for complex ideas

Каждый слайд несёт **одну** мысль. Если мысль слишком сложна — разбить на серию слайдов, но обязательно с прогрессбаром или нумерацией, чтобы зритель понимал «1 из 3» и не терялся.

- **Дефолт:** один слайд = одна мысль = один action title.
- **Серия 2–4 слайдов:** показать прогресс в заголовке («Шаг 1 из 3 — диагностика», «Шаг 2 из 3 — варианты», «Шаг 3 из 3 — решение»). Или маленький индикатор «1/3», «2/3», «3/3» в углу.
- **Серия > 4 слайдов на одну мысль:** скорее всего это уже глава, а не мысль. Открыть её разделителем (`divider`) и обращаться как с разделом.
- **Не смешивать две мысли «потому что не хватает места».** Лучше дополнительный слайд, чем перегруженный.

| BAD | GOOD |
|---|---|
| Слайд «Метрики и риски Q2» с 4 KPI слева и 3 рисками справа | Два слайда: «Q2 закрыли с превышением на 12%» (метрики) + «2 риска требуют внимания CEO» (риски) |
| Слайд «Анализ воронки» с описанием 5 этапов воронки + конверсий + выводов | Серия 3 слайдов: «Воронка теряет 60% на этапе 3 (1/3)», «Причина — таймаут API (2/3)», «Фикс уже в проде, ждём данные за июль (3/3)» |

**STOP signals.**
- На слайде больше одного action title-кандидата — разбить.
- В заголовок попало «и» / «а также», соединяющее две независимые мысли — разбить.
- Серия слайдов без прогрессбара — добавить, иначе зритель потеряется.

## Rule 6 — Metrics: simple, labelled, reproducible

Каждая цифра должна быть:
1. **Подписана** (что измеряем).
2. **С единицей измерения** (% от чего, ₽, штук, FTE, мс).
3. **С периодом** (за Q2, MoM, YoY, на 18.05.2026).
4. **С базой сравнения** для процентов и динамики (vs Q1, vs план, vs прошлый год).
5. **Воспроизводима** — у читателя должна быть возможность сказать «эту цифру я могу пересчитать из источника X».
6. **Консистентна по деку** — одна метрика = одно значение, одно округление
   и одна база на всех слайдах; агрегаты сходятся (сумма долей = 100%,
   доля × база = абсолют, итог = сумме строк). Опытная аудитория ловит
   «25% на слайде 5, 23% на слайде 7» за две секунды — и дальше читает
   с фильтром «а тут можно верить?».

| BAD | GOOD |
|---|---|
| «+12%» | «+12% выручки за Q2 vs Q1» |
| «247» | «247 активных команд на 18.05.2026» |
| «98% качество» | «98% SLA по ответам в чате (медиана за апрель 2026, n=1247)» |
| «Рост в 2 раза» | «×2 DAU за 6 месяцев: 12k → 24k (ноя 2025 → май 2026)» |
| «Сэкономили деньги» | «–18 млн ₽ операционных расходов за Q2 vs план» |

**Какие подписи обязательны** под метрикой / графиком:
- Что за метрика (полное название без жаргона).
- За какой период.
- Источник данных (если внутренняя аналитика — указать систему: «КАИ», «GA4», «AppMetrica»).
- Если выборка — её размер (n=1247).

**STOP signals.**
- Цифра без единицы измерения → STOP, попросить контекст.
- «Рост на N%» без базы сравнения → STOP.
- График без подписи оси Y → STOP.
- Метрика, которую невозможно объяснить аудитории за 10 секунд («адъюстированный CAC ex-байбэк») — упростить или перевести в производное.
- Та же метрика с другим значением, округлением или базой на другом слайде — STOP, привести к одному источнику истины.

## Rule 7 — Data over opinions; precise wording

Заменяй оценочные слова конкретными числами. Если числа нет — поищи прокси или признайся, что числа нет.

**Запрещены без конкретики:**
- «большинство», «почти все», «многие», «значительная часть» → процент или количество.
- «улучшили», «оптимизировали», «усилили» → метрика, которая выросла, и на сколько.
- «существенный рост», «заметное снижение» → число.
- «лидер рынка», «один из крупнейших» → доля рынка или место в рейтинге.
- «эффективно», «качественно», «оперативно» → метрика эффективности / качества / скорости.

| BAD | GOOD |
|---|---|
| «Улучшили процесс согласования» | «Сэкономили 1 FTE за счёт автоматизации согласований» |
| «Большинство пользователей довольны» | «83% NPS-промоутеров (n=2415, апрель 2026)» |
| «Значительно ускорили ответы» | «Медиана ответа: 4 мин → 45 сек (vs Q1)» |
| «Усилили команду» | «+4 найма в Q2: 2 senior eng, 1 designer, 1 PM» |
| «Сервис стал стабильнее» | «Uptime 99.2% → 99.8% за квартал» |

**STOP signals.**
- В буллете есть «большинство», «почти все», «значительный», «существенный» — STOP, попросить число.
- Глагол «улучшили / оптимизировали / усилили» без метрики и дельты — STOP.
- «Лучше» / «больше» / «быстрее» без vs чего — STOP.

## Rule 8 — Comparisons: always vs what

Любое сравнение должно явно называть базу. «Лучше» само по себе не имеет смысла.

| BAD | GOOD |
|---|---|
| «Конверсия выросла» | «Конверсия выросла с 2.1% до 3.4% за Q2» |
| «В 2 раза лучше» | «В 2 раза быстрее, чем в Q1: 4 сек → 2 сек медиана отклика» |
| «Опережаем рынок» | «Растём на 47% YoY при рынке +12% (источник: AdIndex Q2 2026)» |
| «Запустили быстрее плана» | «Запустили на 3 недели раньше плана (план — 30 мая, факт — 9 мая)» |

**Базы сравнения, которые работают:**
- Предыдущий период (vs Q1, MoM, YoY).
- План / прогноз / таргет (vs план).
- Бенчмарк рынка / конкурента (vs средний по индустрии).
- Бейзлайн до изменения (до запуска фичи / до реорга).

**STOP signals.**
- «Стало лучше / больше / быстрее» — STOP, спросить vs чего.
- «×2», «×3» без указания исходного значения — STOP.
- «Опережаем рынок» без цифры рынка — STOP.

## Rule 8a — Причинность и честные срезы

Рост **после** запуска ≠ рост **из-за** запуска. Показанный лучший сегмент ≠ картина по всем. Опытная аудитория (комитет, финансы) начинает разбор именно с этого — слабая причинность рушит доверие ко всему деку.

- **Причинность заявляется только с контролем.** «Конверсия +25% за счёт X» требует A/B-теста или явного контроля (регионы без X, до/после с одинаковым окном при стабильном фоне). Контроля нет → формулируй хронологию, не причину: «после запуска X» + честная оговорка, если фон менялся (сезон, маркетинг, конкурент).
- **Cherry-picking запрещён.** Приводишь лучший регион / сегмент / период — покажи и полный срез, или явно пометь: «лучший сегмент; в среднем по всем — Z». Есть данные только по одному срезу — так и написать.
- **Качественные утверждения — с N и методом.** «Пользователям нравится» без выборки — не факт. Одна цитата — иллюстрация, не доказательство.

| BAD | GOOD |
|---|---|
| «Запустили AI-агента — конверсия выросла на 25%» | «A/B на 5% трафика: test 30% vs control 24%, статзначимость 95%» |
| «В Москве AOV вырос на 50%» (показан лучший город) | «AOV: Москва +50%, в среднем по городам +12%» |
| «Водители жалуются на выплаты» | «34% обращений водителей за май — про выплаты (n=1 214)» |
| «После редизайна NPS вырос» (совпало с промо-акцией) | «NPS +12 п.п. за месяц после редизайна; параллельно шло промо — вклады не разделены» |

**STOP signals.**
- «За счёт», «благодаря», «привело к», «драйвер — X» без A/B или явного контроля — переформулировать в «после» или назвать контроль.
- Показан один регион/сегмент/период, а данные есть шире — STOP, полный срез или пометка.
- «Пользователи говорят», «клиенты просят», «команда считает» без N и метода сбора — STOP, попросить выборку или переформулировать как гипотезу.

## Rule 9 — Tasks in terms of result, not process

Когда говоришь о задачах, целях, планах, инициативах — формулируй через **измеримый результат**, а не действие.

| BAD (процесс / действие) | GOOD (результат) |
|---|---|
| «Внедрить новую CRM» | «Снизить time-to-response с 4 ч до 30 мин к Q4» |
| «Провести 5 интервью с пользователями» | «Понять, почему 40% бросают онбординг — к 1 июня» |
| «Запустить рекламную кампанию» | «Привести 10k новых регистраций при CAC ≤ 800 ₽ за июнь» |
| «Оптимизировать процесс» | «Сократить цикл согласования с 7 дней до 2 к концу Q3» |
| «Усилить команду» | «Закрыть 4 senior-роли (2 eng, 1 design, 1 PM) к 30 июня» |

Это не отменяет описание шагов в плане. Но **слайд** показывает результат; шаги — в приложении или в устном рассказе.

**STOP signals.**
- Задача начинается с «провести», «внедрить», «осуществить», «оптимизировать» без метрики и срока — переписать в результат.
- В планах квартала нет ни одной цифры — STOP, попросить таргеты.

---

## Rule 10 — Facts vs opinions: never mix

Факт можно проверить. Мнение — нет. На слайде они должны быть **разделены визуально и текстуально**.

- **Факт:** «MAU 1.2M в апреле 2026 (источник: AppMetrica)».
- **Мнение:** «Мы думаем, что причина роста — рекомендательный фид».
- **Гипотеза:** «Гипотеза: фид даёт +30% retention. Проверим A/B в мае».

Если на слайде есть и то, и другое — пометь явно: «Факт:» / «Гипотеза:» / «Наша оценка:» / «План:». Или раздели на два блока с разными подзаголовками.

| BAD (мнение подано как факт) | GOOD (явная разметка) |
|---|---|
| «Пользователи любят новый интерфейс» | «Факт: NPS +12 п.п. за месяц после редизайна. Гипотеза: причина — упрощённая навигация» |
| «Рынок растёт благодаря digital-трансформации» | «Факт: рынок +47% YoY (AdIndex). Наша оценка: основной драйвер — digital, доля выросла с 30% до 42%» |
| «Команда стала продуктивнее» | «Факт: 14 фич в Q2 vs 9 в Q1. Наша оценка: помог переход на squad-структуру в марте» |

**STOP signals.**
- На слайде утверждение, которое нельзя проверить, без пометки «гипотеза / оценка / мнение» — STOP, разметить.
- Числа и мнения в одном буллете без разделения — переписать в два.

---

## Rule 11 — Non-results: appendix or cut

Если инициатива съела время, но **не дала результата** — это не повод занимать слайд в основной части. Варианты:

1. **Cut.** Если про неё не спросят — убрать совсем. Усилия — это не достижение.
2. **Appendix.** Если про неё могут спросить (защита бюджета, ретроспектива, обучение) — в приложение, **одним слайдом** с честным «не дало результата, потому что X, выученный урок Y».
3. **Слайд в основной части — только если урок важнее результата** (научились, что подход не работает; завершили без долга; внутренний релиз процесса). Тогда заголовок: «Гипотеза X не подтвердилась — закрыли направление, освободили 2 FTE».

| BAD | GOOD |
|---|---|
| Слайд «Что мы делали в Q2» с 10 буллетами активностей, 3 из которых ни к чему не привели | Слайд «Q2 — 7 запусков с результатом» (основной) + слайд в appendix «3 закрытых эксперимента — почему» |
| «Запустили A/B по X, провели исследование Y, попробовали Z» — без результатов | «X не подтвердил гипотезу, закрыли. Y → +12% retention, раскатываем. Z в работе» |

**STOP signals.**
- В основной части слайд про активность без результата — STOP, перенести в appendix или cut.
- «Мы старались» / «Мы инвестировали усилия в X» без числового исхода — это не контент.

---

## Rule 12 — Every slide answers «зачем он в деке»

Перед тем как оставить слайд в финальной колоде, ответь себе **в одном предложении**: зачем этот слайд здесь? Если ответ — «для полноты картины», «чтобы было», «логично сюда подходит» — слайд лишний.

Хорошие ответы на «зачем»:
- «Чтобы доказать тезис {N}» (опора для action title другого слайда).
- «Чтобы аудитория приняла решение Y» (без этого слайда решение не принять).
- «Чтобы развеять возражение Z» (предвосхищаем вопрос).
- «Чтобы передать масштаб» (без этого слайда числа дальше не считываются).

| BAD ответ на «зачем» | Что делать |
|---|---|
| «Чтобы было плавнее» | Cut. Плавность — это структура, а не отдельный слайд. |
| «Это контекст» | Свернуть в одно предложение и положить в exec summary. |
| «Стейкхолдер X обычно спрашивает» | Положить в appendix, не в основную часть. |
| «Логично между разделами» | Это разделитель (`divider`), не контентный слайд. |

**STOP signals.**
- Не можешь ответить на «зачем» за 5 секунд — слайд под вопросом, спроси автора.
- Ответ начинается с «потому что обычно так делают» — слайд лишний.

---

## Rule 13 — Standalone clarity: deck readable without the speaker

Колода должна быть понятна **без устного объяснения**. Это не значит, что устное добавляет 0 — это значит, что слайды самодостаточны как документ.

Проверка: отправь колоду человеку, который не был на встрече. Он должен:
- Восстановить вывод по заголовкам (Rule 2).
- Понять каждую цифру по подписям (Rule 6).
- Найти определения терминов на слайде (а не в голове докладчика).

| BAD (нужен спикер) | GOOD (standalone) |
|---|---|
| График без подписи осей; в речи: «по горизонтали — недели Q2» | Подписи осей: «Недели Q2 (1–13)» |
| Заголовок «Динамика»; в речи: «вот тут провал из-за майских праздников» | Заголовок «Май: провал из-за праздников, к концу месяца восстановились» + подпись провала на графике |
| Аббревиатура «КАИ» без расшифровки; в речи: «корпоративный аналитический инструмент» | На первом упоминании в деке: «КАИ (корпоративный аналитический инструмент)» |

**STOP signals.**
- На слайде есть отсылка «как видно», «здесь», «вот это» без визуального якоря — STOP.
- Понимание слайда требует знания контекста, которого нет в деке — добавить контекст или cut слайд.

---

## Rule 14 — Cut what can be cut

Если фразу / буллет / слайд можно убрать без потери смысла — убрать. Колода тем сильнее, чем меньше в ней лишнего.

Кандидаты на удаление:
- Вводные фразы: «Хочу обратить ваше внимание на то, что…», «Стоит отметить, что…», «Важно понимать…». Просто скажи, что хочешь сказать.
- Дублирующие буллеты: два пункта про одно с разной формулировкой → один пункт.
- Слайды-связки: «Прежде чем перейти к Y, давайте вспомним X». Если без них дек разваливается — структура плохая, не добавляй слайд-костыль.
- Полные предложения в буллетах, когда хватает фразы: «Команда выросла на 4 человека в Q2» → «+4 найма в Q2».
- Эпитеты: «значительный», «существенный», «впечатляющий», «уникальный», «прорывной» — почти всегда лишние.

| BAD | GOOD |
|---|---|
| «В рамках проделанной работы мы достигли значительных результатов в области повышения качества» | «Качество выросло — NPS +12 п.п.» |
| «Важно отметить, что динамика положительная и устойчивая на протяжении нескольких кварталов» | «Положительная динамика 3 квартала подряд» |
| «Стоит обратить внимание на то, что показатель достиг целевого значения» | «План выполнен» |

**STOP signals.**
- В тексте есть «хочу отметить», «стоит подчеркнуть», «важно понимать» — почти всегда cut.
- Буллет длиннее 60 знаков — переписать короче или вынести в подпункт.
- Слайд можно убрать и презентация всё ещё рассказывает свою историю — убрать.

## Rule 15 — Workflow: how to write a slide

When filling in any content slide:

1. **Сформулируй вывод одной фразой.** Это твой кандидат на action title (Rule 2). Если не можешь — у тебя нет ясной мысли или их две (Rule 5).
2. **Проверь, не лишний ли слайд.** Ответь на «зачем он в деке» (Rule 12). Если ответ слабый — cut.
3. **Напиши заголовок-вывод.** Активный, с цифрой, со сравнением (Rule 2, 6, 8).
4. **Напиши тело: вывод → детали.** Сначала ключевое, потом аргументы (Rule 1).
5. **Прогони по чек-листу:**
   - Простой язык, короткие предложения (Rule 3)?
   - Цифры подписаны, с единицей, с периодом, с базой (Rule 6, 8)?
   - Причинность с контролем, срезы честные, качественные утверждения с N (Rule 8a)?
   - Нет оценок вместо данных (Rule 7)?
   - Факты и мнения разделены (Rule 10)?
   - Можно понять без меня (Rule 13)?
   - Что можно убрать — убрать (Rule 14)?
6. **Прочитай дек по заголовкам.** Восстанавливается история? Если нет — чинить, до тех пор пока да.

## Rule 16 — Не выноси на пользователя наши ограничения

Уточняющие вопросы пользователю бывают двух типов:

1. **Про intent — это хорошо и нужно.** Аудитория, главная мысль, theme, архетип дека, есть ли у пользователя готовые фото. Эти вопросы открывают пространство решений, которое нельзя инферить из контента.
2. **Про наши собственные ограничения — это запрещено.** «У нас timeline вмещает 4 события, а у тебя 6 — что выбираем?», «У нас нет шаблона на 5 метрик — разрежем на 3+2 или урежем?», «Какой набор слайдов вы хотите?» — это плохие вопросы, потому что они перекладывают **нашу** инженерную задачу на пользователя. Пользователь пришёл с контентом, не с задачей подбирать шаблон.

### Что делать вместо limitation-вопроса

1. **Look at the family catalogue first.** Пройди по [families-eda.md](families-eda.md) и карте «контент → семейства» ([deck-archetypes.md](deck-archetypes.md), раздел 0) — под форму контента почти всегда есть семейство. Для 5–6 событий с датами роутер `timeline` сам построит прямую линию; для 5 метрик `metrics` сам уйдёт в GENERATE-сетку.
2. **Доверься роутерам и сплиту.** Роутеры columns/takeaways/timeline/metrics сами решают FILL↔GENERATE по вместимости и fill-ratio и печатают причину при сборке; за пределами их диапазонов — сплит с ребалансом (7 тезисов → плитки 4+3, 8+ вех → два таймлайна по фазам).
3. **Генеративные ветки.** Если готового слайда нет — плитки (reasons/takeaways) и прямой таймлайн собираются из атомов стиля в канве шаблона. Если и они не ложатся — честно скажи пользователю, что пока не соберёшь красиво (SKILL.md «что честно НЕ умеет»); НЕ выдумывай раскладку.
4. **Сообщи финальный выбор пользователю как факт**, не как вопрос. Это делается на шаге 2 SKILL.md (план дека → STOP), где пользователь правит, если не согласен.

**Граница правила — дословный текст пользователя (2026-07-07).** Silent-adapt применяется к контенту, который мы пишем или компонуем сами. Готовые формулировки пользователя молча не переписываются: примерь дек целиком, потом ЕДИНЫЙ fit-отчёт с вариантами на выбор — [content-assembly-rules.md §2.2](content-assembly-rules.md). Это intent-вопрос («какая формулировка приемлема») по всему деку разом, а не limitation-пинг-понг по слайду.

### Примеры

| Bad (limitation-вопрос) | Good (silent inference) |
|---|---|
| «У нас 6 событий, а готовый timeline вмещает 4 — какой вариант выбираем?» | Молча отдать роутеру `timeline` (N=5–6 → прямая линия во всю ширину), показать в плане: «Слайд 4 — таймлайн, 6 вех» |
| «У нас 5 метрик не ложатся в сетку 3. Разрезать 3+2 или урезать?» | Молча отдать `metrics` (N=5 → GENERATE-сетка) или разнести 3+2 на два слайда — по плотности контента; показать в плане |
| «У нас 7 тезисов — разрежем на 2 слайда, сгруппируем, или урежем?» | Молча собрать плитки `reasons` (7 → ряды 4+3 на одном слайде), показать в плане |
| «Какой набор слайдов вы хотите в деке?» | Молча выбрать архетип из [deck-archetypes.md](deck-archetypes.md), показать план на шаге 2 |

### Когда вопрос всё-таки уместен

Это intent-вопросы — оставляем их без изменений:

- **Шаблон** — спрашиваем всегда первым (жёсткое правило 2 SKILL.md), даже когда выбор из одного.
- **Архетип не сходится** — пользователь дал запрос, который не подходит ни к одному архетипу в [deck-archetypes.md](deck-archetypes.md). Спроси какой ближе.
- **Нет ассета у пользователя** — выбран вариант с фото (cover, columns three_photos, images), а своих фото пользователь не дал. Предложи пул «Нейро-фото Еда» или вариант без фото.
- **Численные данные** — пользователь говорит «график динамики», но не дал цифр. Это intent-вопрос (данные у пользователя, не у нас), не limitation.
- **Главная мысль** — Step 1 SKILL.md. Без неё дек не собирается.

**Правило**: если вопрос можно сформулировать как «у нас не помещается / у нас нет шаблона / шаблон поддерживает только N» — это limitation-вопрос, не задавай его. Если вопрос — «расскажи мне про контекст / аудиторию / смысл / данные» — это intent-вопрос, задавай.

**STOP signals.**
- В вопросе появилось «у нас», «наш шаблон», «timeline вмещает», «слайд поддерживает только», «не помещается» — STOP, это limitation-вопрос. Замени на silent adaptation.
- Вопрос предлагает пользователю выбрать «или урежем, или разрежем, или промёрджим» — STOP, выбери сам и покажи в outline.
- Вопрос про technical structure («сколько слайдов делаем», «какой набор слайдов») — STOP, инфериь из контента + архетипа.

## Rule 17 — Слот — это РОЛЬ, а не поле для заполнения (+MECE)

Каждый слот дизайнерского слайда несёт роль, которую видно по его заглушке:
«Что показывает график, единицы измерения» — заголовок графика, «Подзаголовок
слайда» — смысловой подзаголовок. Заполняй слот ЕГО содержанием или оставляй
пустым (опциональные слоты чистятся сами) — **пустой слот всегда лучше текста
«лишь бы заполнить»**.

Перед сборкой прогони ВСЕ тексты слайда одним проходом:
- **Роль:** каждый текст стоит в СВОЁМ слоте? (заголовок графика — в подписи
  графика, а не в подзаголовке слайда);
- **Необходимость:** что потеряет читатель, если этот текст убрать? Ничего —
  убрать (дисклеймеры «данные иллюстративные», повторы заголовка, «для
  контекста» — первые кандидаты);
- **MECE:** тексты слайда не пересекаются по смыслу (mutually exclusive) и
  вместе покрывают мысль слайда без дыр (collectively exhaustive); то же —
  между слайдами дека.

| BAD | GOOD |
|---|---|
| Подзаголовок: «Доля задач, закрытых Claude, %» + подпись графика: «Иллюстративные данные: пилот в трёх командах» | Подзаголовок: пусто. Подпись графика: «Доля задач, закрытых Claude, % от потока команды» |
| Комментарий сплошным жирным абзацем | Комментарий = жирный лид-вывод + тело регуляром (роли абзацев дизайнера) |

**Реальный кейс (2026-07-03, дек Claude):** описание графика попало в
подзаголовок, в подпись графика — бессмысленный дисклеймер, комментарий — весь
жирный. Пользователь: «не пытаться заполнить все поля — вычитывать и
челленджить на MECE, логичность, читаемость и необходимость».

## Rule 18 — Один тезис — не список

Список существует от двух пунктов. Если после подзаголовка (в карточке, в
колонке, в теле слайда) остался ОДИН тезис — он пишется абзацем без буллета:
буллет при единственном пункте обещает перечисление, которого нет
(user-правило 2026-07-29, боевой пример — смоук Городских, слайды 6–7).

- Движок страхует механически: при заполнении спискового слота единственным
  пунктом дизайнерский буллет снимается автоматически (fill,
  `solo_bullet_stripped` в отчёте сборки).
- Но правило прежде всего КОНТЕНТНОЕ: один тезис — повод спросить себя, тезис
  ли это или недоразвёрнутая мысль. Либо доразверни до 2–3 пунктов
  (если есть чем — без воды, Rule 17), либо переформулируй в полноценный
  абзац-вывод.
