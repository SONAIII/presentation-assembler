# Рецепты кастом-структур (family: custom)

Проверенные скелеты для контента, которому НЕТ семейства и НЕТ генеративной
структуры — консалтинговая геометрия, собираемая HTML-хэтчем. Каждый рецепт
прогнан через конвейер (обмер → конверсия → PowerPoint-рендер) и сверен
глазом; скелеты живут в `examples/custom_recipes.html` (слайд = `html_slide`
в deckspec, там же демо-числа). НЕ верстай эти структуры с нуля — копируй
скелет и подставляй данные.

Порядок применения прежний (custom-html.md): сначала fill, потом structure,
потом реворд — рецепты берутся, только когда роутер уже выбрал custom.

| Рецепт | `html_slide` | Когда |
|---|---|---|
| Матрица 2×2 | 0 | приоритизация, портфель, позиционирование |
| Водопад | 1 | разложение величины на вклады: юнит-экономика, P&L-мост |
| Гантт | 2 | план по времени, фазы и вехи (дизайнерский гантт #31 не влез/не подошёл) |
| Воронка | 3 | последовательные конверсии |
| Оргсхема | 4 | иерархия команд (дизайнерский orgchart #34 не подошёл) |
| Статус-матрица | 5 | RAG-статусы + готовность по проектам |
| Бейдж-карточки | 6 | контент с типизированными атомами (badge · title · pill · caption; роли с лид-инами) — процессные и организационные слайды «шаги + роли», перевёрстка структурного исходника ([content-assembly-rules.md §1.0](content-assembly-rules.md)) |
| Витрина скринов | 7 | скрины приложения с подписями форматов (медиакиты, продуктовые обзоры) — телефоны нативными рамками |

## Общие правила

- **Низ канвы — якорь номера страницы** (фидбек-репорт 2026-07-20): контракт
  `.slide` — `padding:79px 125px 120px`, контент заканчивается на y≤960;
  полоса футера/номера (y 981→1015) неприкосновенна, гвард A15 валит сборку
  за любой атом в ней или за канвой. Абсолютные контейнеры рецептов считай
  от ФАКТИЧЕСКОГО верха контента: при двухстрочном заголовке контент-зона
  начинается на ~263 (79 + 140 + 44) → высота ≤697; при однострочном —
  на ~193 → высота ≤767. Не влезает — ужимай карточки/тексты (`flex:1`
  растянет карточки по колонке, но их min-content должен помещаться), а не
  нижний отступ.
- **Числа → пиксели пересчитывай сам** и оставляй комментарий с формулой
  в HTML (масштаб водопада, ширины воронки, календарь гантта) — следующему
  агенту/правке нужна арифметика, не магические числа.
- **Линии и стрелки — `data-line`** (нативные, редактируемые):
  `<div class="nline" data-line="arrow" style="width:…;height:3px">`.
  Токены: `arrow` (наконечник в конце: вправо/вниз), `arrow-start`,
  `arrow-both`, `dashed`. Толщина = короткая сторона бокса, цвет —
  background. Только горизонталь/вертикаль; диагонали и Г-образные связи —
  SVG-слоем (ниже).
- **Круги/эллипсы** — `border-radius:50%` конвертируется в нативный oval
  (вехи гантта, RAG-точки).
- **Сеть связей (оргсхема и любые «карточки + линки»)** — ОДИН абсолютный
  `<svg>` на всю композицию, в DOM ДО карточек (ляжет под ними), пути
  `stroke="#4F4E49" fill="none"`. Слой растеризуется одной картинкой —
  связи не редактируются поштучно; повторяющийся паттерн — кандидат
  в GENERATE (воронка продвижения, custom-html.md).
- **Редполитика инфографики** — custom-html.md §Инфографика: жёлтый — одна
  роль на слайд (активная фаза гантта, верх воронки, «делаем сейчас»);
  стрелки/линии ink или серые; `--ok`/`--no` — только семантика.

## Заметки по рецептам

- **2×2:** оси — два `data-line` со стрелками по краям области; подписи осей
  ghost-каптонами У КОНЦОВ стрелок (не поворачивай текст — поворот не
  конвертируется). Квадранты — карты `--grey`, приоритетный — жёлтый;
  элементы — белые пилюли.
- **Водопад:** старт и итог — ink-бары от базовой линии; спады серые, рост
  жёлтый; мосты — `data-line="dashed"` серым НА УРОВНЕ кумулятивной суммы
  (соединяют верх/низ соседних баров — сверь по рендеру, это самое частое
  место ошибки). Значения над барами, категории под базовой линией.
- **Гантт:** сетка месяцев — ghost-заголовки с шагом столбца; фазы — серые
  плашки, активная — жёлтая; вехи — ink-круги ВНУТРИ плашки; «сегодня» —
  вертикальный `data-line="dashed"` цвета `--grey-line` с датой-подписью
  снизу. Пересчёт даты в x: `колонка_имён + гэп + ширина_месяца × доля`.
- **Воронка:** ступени сужаются К ЦЕНТРУ (`margin:0 auto`); конверсии —
  ghost-каптоны в зазорах справа, у фиксированного x за пределами ступеней;
  сквозная конверсия — строкой под воронкой.
- **Оргсхема:** карточки абсолютом по сетке центров; шины и отводы — один
  path (`M x y V…H…`). Считай координаты от ЦЕНТРОВ карточек и оставляй
  их комментарием. Руководитель — жёлтая карта.
- **Статус-матрица:** строки — grid (НЕ `<table>` — RAG-точки и донаты в
  ячейках стали бы оверлеями поверх нативной таблицы); разделители — div
  1px `--grey`; готовность — мини-донат из glyphs (`donut.svg`, пересчёт
  дуги в комментарии файла), статус — круг 32px `--ok`/`--yellow`/`--no`.
- **Бейдж-карточки:** две колонки с заголовками-лейблами; слева карточки
  шагов (ink-бейдж ярлыка → заголовок → жёлтая пилюля ключевой сущности →
  ghost-подпись метода, прижатая к низу `margin-top:auto`), справа карточки
  ролей (ink-плашка имени + строки-буллеты с жирными лид-инами). Точки
  буллетов — РЕАЛЬНЫМИ `<div>`-кругами (`::before` не конвертируется),
  станут нативными OVAL. Жёлтый — одна роль: пилюли. Нумерованные табы
  сюда НЕ добавлять: колонки параллельны, номера навяжут ложный порядок
  ([quality-gates.md](quality-gates.md) «Нумерация = последовательность»).
  Каждому атому исходника — свой элемент скелета; склейка атомов в абзац —
  та самая «стена текста», ради запрета которой рецепт существует.
- **Витрина скринов:** подпись формата НАД каждым телефоном (`.ph-cap`,
  фидбек E медиакита); рамка `.ph-frame` (тонкая, ink, 9px) конвертируется
  в НАТИВНЫЙ редактируемый roundRect — не запечённая картинка; скрин —
  `<img src="file:///абсолютный/путь.png">` внутри `.ph-screen`
  (cover-кроп → srcRect). Теней нет намеренно — бренд без теней. Для
  ФОТО-СЛОТОВ шаблонных семейств (images/three_pics) телефон-PNG делает
  `scripts/phone_mockup.py` (тонкая рамка, прозрачный фон, тень выключена
  по умолчанию) — но там подписи на каждую картинку не будет, у three_pics
  только общий заголовок; нужны подписи → этот рецепт.

## Чего в рецептах сознательно нет

Поворотов (ромбы-майлстоуны, наклонные подписи) и диагональных нативных
линий — обмерщик работает с axis-aligned боксами. Визуально это закрывает
SVG-слой; если понадобится редактируемость — вопрос владельцу скилла,
не самодельный хак в деке.
