# Кастом-рецепты «Хурала Райдтеха» (family: custom)

Дизайн-система — [assets/ridetech-khural/deck.css](../assets/ridetech-khural/deck.css)
(канон снят с эталонных слайдов шаблона v1.0); механика хэтча —
[custom-html.md](custom-html.md). Хром: светлый лэйаут «Title» (default —
контентные слайды шаблона белые), тёмный «Black title» (фон HTML тёмный →
движок выберет сам по by_bg профиля). Заголовок слайда — ВСЕГДА `.h1`
(уедет в TITLE-плейсхолдер хрома); низ 120px не занимать (полоса футера).

## Палитра и типографика — коротко

- Светлый слайд: белый фон, чёрный текст; карточки/пилюли — серые `#ECEDF0`.
- Тёмный слайд (`.slide.black`): чёрный фон, белый текст; карточки `#1c1d21`.
- Семантика: зелёный `#71FFB5` = позитив/текущее, красный `#FF9189` = негатив
  (ТОЛЬКО по смыслу, не как украшение); жёлтый `#FFDE40` — точечный акцент.
- Шрифты: `YS Text Wide Bold` — заголовки/значения; `YS Text Bold` —
  лейблы/названия; `YS Text Regular` — боди. Кегли канона: h1 64, боди/тезисы
  32, лейблы 28, значения 88–115, гигант statement 344.

## Карта «атом → эталон» (откуда снят канон)

| CSS-класс | Эталон в шаблоне |
|---|---|
| `.card` | Rounded Rectangle #22/#25 (fill dk2, r≈48px, обводки нет) |
| `.pill` | atom:milestone_date #36 (полное скругление, серая, текст 32) |
| `.tag` | atom:metric_tag #34 (обводочная пилюля, 28px) |
| `.stepdot` | atom:arrow #36 (круг 114px, чёрный, глиф белый) |
| `.value`/`.label` | atom:metric_value/desc #34 (115px / 28px) |
| `.hl.good`/`.hl.bad` | atom:highlight_* #28 (C1FFDE / FFC7C7, r≈14px) |
| `.display` | Title 2 statement #17 (344px) |

## Рецепты

### 1. Схема / флоу (этапы со стрелками)
Горизонтальная цепочка: `.pill` (этап) → `.stepdot` со стрелкой «→» →
`.pill` … Текущий этап — `.pill.green`. Подписи под этапами — `.label`.
Прямой аналог оси таймлайна донора — но для НЕ-временных цепочек
(процесс, воронка конверсии, пайплайн).

### 2. Орг-структура
`.org` + svg-линии связей + `.node`-пилюли (голова — `.node.head`).
Фото людей — только из материалов пользователя (`.ava`), иначе серый круг.
Правило то же, что у Городских: донorships нет — орг-чарты всегда custom.
**Вертикаль:** нижний ярус узлов прижимается к нижнему полю (низ ≈ y 960,
не выше y 900) — ярусы разводи воздухом МЕЖДУ уровнями, а не полосой
пустоты под схемой (гвард A18; хэндофф Ultima — обе орг-схемы «всплыли»).

### 3. Сравнение до/после, было/стало
Две `.card` в ряд: в левой негатив (значение `.value.red`), в правой
позитив (`.value.green`). Вердикт-строка — `.hl.good` под карточками.

### 4. Матрица / квадрант
Оси — `.nline` (2px), подписи осей — `.label`; объекты — `.tag`-пилюли
по позициям. Квадрант-акцент — заливка `#ECEDF0` со скруглением `--r-card`.

### 5. Канбан / статусы
3–4 колонки `.card`, шапка колонки — `.ct` + счётчик `.bignum`;
элементы — `.pill` в столбик с зазором 16px. Статусная семантика цветом
только по смыслу (готово `.pill.green`).

### 6. Метрика + буллеты (N блоков «цифра со списком опор»)
Кейс «Q3 в четырёх цифрах» (user-фидбек 2026-08-07, коммент 5 дека Beri
Zaryad): у каждой метрики 2–4 поддерживающих пункта, а карточные доноры
несут только value+desc — НЕ ужимай пункты в одну строку (потеря структуры,
SKILL.md шаг 3), собирай custom. 3–4 колонки `.card`: сверху `.tag`-пилюля
(ярлык), под ней `.value` (при 4 колонках — 88px, не 115), ниже пункты опор
НАСТОЯЩИМ `<ul><li>` боди-кеглем 28–32 — конвертер соберёт нативные буллиты
канона (маркер «•», как на дизайнерском доноре #42); дефисы/точки руками
НЕ верстать, дизайнер такое бракует (хэндофф Ultima, O2).
Сентимент значений — `.value.green`/`.value.red` только по смыслу. Если
пунктов на блок ≥5 — это уже не метрики, а колонки текста: реворд или split.
**Вертикаль:** карточки тянутся до нижнего поля (низ ≈ y 960, не выше
y 900) — свободное место между заголовком и карточками, не под ними
(гвард A18; хэндофф Ultima — слайд метрик кончался на 74.5% высоты).

## Пре-flight кастома

`python3 scripts/preflight.py --custom-only` (<1 c). Превью одного слайда:
`python3 scripts/html_preview.py <file.html>`; обмер — `node scripts/html_measure.mjs`.
Приёмка — как у всех: crash → lint → PP-рендер, «Repair»-диалога быть не должно.

## Поля и плашки (валят сборку — custom-html.md «Вёрстка в полях и плашках»)

Поля канвы Хурала: **54px лево/право, 40px верх, 120px низ** — вся сетка
внутри них (движок валит атом за полями). **Вертикаль:** контент прижат к
нижнему полю — низ ≈ y 960, не выше y 900; воздух между заголовком и блоком,
не под блоком (гвард A18 валит «всплывший» слайд с пустой полосой снизу
больше 8% контентной высоты). Значения: 3 колонки ≤115px,
4 колонки ≤88px, длинные числа («22,400») → 72px или «22.4K». `.tag`/`.pill`
со статусами — только в потоке (inline-flex, паддинг задаёт ширину), не
absolute поверх текста. Самое длинное слово заголовка не уже его колонки.
Шрифтовая проба конвертера сверит обмер с PP-метрикой — при подменных
шрифтах сборка честно падает.
