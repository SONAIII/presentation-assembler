# Комитет: готовые макеты из реальных слайдов

Выбор: `template: комитет` или `committee`. Перед работой прочитай
[committee-design.md](committee-design.md) и просмотри нужные изображения
в `assets/committee/reference/`. Обязательна также проверка содержания по
[content-challenge.md](content-challenge.md).

Источники оформления: сентябрьский `Комитет_Сходить_09092026_preread`,
страницы 1, 2, 4, 8, 25, 29, 30, и финальный слайд по дебиторке.
Цветовые акценты берутся из дебиторки: крупный синий из PDF не используется.
Ранее предложенные пустые карточные макеты пользователь отклонил: они
удалены из набора и не служат образцами.

## Выбор композиции

| Семейство / вариант | Реальный образец | Содержание |
|---|---|---|
| `cover/source` | PDF стр.1 | Крупное название, дата слева; без белой полосы |
| `divider/source` | PDF стр.4 | Номер раздела и узкий курсивный заголовок тёмным цветом |
| `summary/source` | PDF стр.2 | Три метрики с объяснением, сравнением и фокусом; таблица направлений снизу |
| `chart_note/source` | PDF стр.8 | Большой график слева, содержательный комментарий справа |
| `dashboard/source` | PDF стр.29 | Один большой и три компактных графика с определениями метрик |
| `priorities/source` | PDF стр.25 | Горизонтальные причины/ограничения и следующий шаг снизу |
| `roadmap/source` | PDF стр.30 | Плотная таблица проектов и статусов; зависимости отдельной колонкой |
| `chart_table/actions` | Финальная дебиторка | Накопительные столбцы и процентная линия сверху; причины, доли, действия и сроки снизу |

Сетка содержательных блоков взята из источника; по замечаниям пользователя
увеличены внутренние поля, снижена плотность и добавлены разделители. Она не меняется при
заполнении. Исходная канва PDF 2065 × 1161 пропорционально приведена к
720 × 405 pt (16:9). Финальная дебиторка масштабирована пропорционально.
Графики и таблицы нативные, редактируемые; скриншоты не заменяют данные.

Готовая исполняемая спека всех восьми макетов:
`examples/committee_smoke.json`. Она заполнена содержательными условными
примерами с плотностью, сопоставимой с исходником. Это **демонстрационные**
данные; не используй их как факты команды. Отдельная спека дебиторки:
`examples/committee_chart_table.json`.

```bash
sh scripts/run.sh scripts/assemble.py templates
sh scripts/run.sh scripts/fit_check.py examples/committee_smoke.json
sh scripts/run.sh scripts/assemble.py build examples/committee_smoke.json -o committee-demo.pptx
```

Команды выполняются из папки скилла. Перед рабочей сборкой согласуй факты и
содержание по SKILL.md; демонстрацию дизайна можно собирать сразу.

## Контракты

`summary`: `heading`, `subtitle`, по три элемента в `labels`, `values`,
`baselines`, `bodies`, `focus`; `table` — до 4 строк × 3 колонки с заголовком.

`chart_note`: `heading`, `chart_title`, `note_heading`, `note_body`;
`charts.chart` — категории и ряды.

`dashboard`: `heading`; `left_title`, `left_subtitle`, `top_title`,
`top_subtitle`, `bottom_title`, `bottom_subtitle`; четыре графика
`charts.main`, `trend`, `step1`, `step2`. Каждый получает свои категории и ряды.

`priorities`: `heading`, `subtitle`, `chart_title`, `callout_label`,
`callout`; `charts.chart` — текстовые категории причин и числовой ряд.

`roadmap`: `heading`, `table` — до 9 строк × 4 колонки, включая заголовок;
`next_heading`, `next_body`. Сохраняй плотность исходного плана; если данных
существенно меньше, выбери другой подходящий образец, не заполняй пустоту.

`chart_table`: `heading`, `unit`, `table` — заголовок и 1–7 строк,
ровно 4 колонки: причина, доля/масштаб, действие, срок. У доли должна быть
понятная база (`ДОЛЯ ДОЛГА ТОП-50`). Для нескольких действий одной причины
оставляй обе первые ячейки продолжения пустыми: они объединятся по вертикали.
У каждого действия свой срок. `Выполнено` выделяется зелёным.
`charts.chart` — 2–24 категории и ровно три ряда **в таком порядке**:
два неотрицательных компонента накопительного столбца в общей единице;
процентная линия со значениями 0–100. Пропуски и NaN не принимаются.

У всех графиков данные задаются как `{categories: [...], series: {имя: [...]}}`.
Источник, период, расчёты и ограничения — в `notes` и evidence. Ограничение,
меняющее трактовку, отражай также в подписи или формулировке на канве.
Переполнение нативной таблицы приводит к ошибке; скрытого обрезания нет.

Каждый chart-донор используется один раз в одном деке — это существующее
ограничение движка chart/OLE. При необходимости повторения нужен отдельный
донор, а не картинка вместо графика.

## Шрифты, рендер и поддержка

Нужны **YS Text Regular/Bold и YS Text Cond Bold Italic**. Узкий курсив —
часть исходного дизайна, его нельзя молча заменять обычным жирным курсивом.
Для финальной дебиторки сохранён YS Text Bold Italic, как в готовом слайде.
На macOS renderer должен видеть и `~/Library/Fonts`, и `/Library/Fonts`.
Сверяй отрендерованный файл с соответствующим исходником; успешный build
не подтверждает правильность шрифта, сетки и плотности.

В `assets/committee/reference/` лежат исторические визуальные образцы:
их текст и цифры нужны для оценки дизайна, а не как факты нового доклада.
Чистый template PPTX содержит только заглушки и нулевые данные.
Происхождение и хэши: `Templates/committee/provenance.json`.
Пин size/MD5/SHA-256 закреплён в `Templates/manifest.json`; сеть не нужна.

Пересборка пакета разработчиком:

```bash
sh scripts/run.sh scripts/build_committee_reference.py '<исходный-комитет.pdf>'
sh scripts/run.sh scripts/upgrade_committee.py '<финальный-слайд-дебиторки.pptx>'
sh scripts/run.sh scripts/inventory_template.py --template Templates/committee/committee-template-v1.pptx --out layouts/committee/_inventory.json --json-only
sh scripts/run.sh scripts/gen_families_md.py --template committee
sh scripts/run.sh -m unittest discover -s evals -p test_committee.py
```

После пересборки обязательны fit/build/render и визуальное сравнение.
