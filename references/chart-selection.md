# Chart selection: говори на языке диаграмм

Метод Джина Желязны («Say It With Charts» / «Говори на языке диаграмм»),
приземлённый на семейства шаблона. Читается **на шаге 2 SKILL.md**, когда
в контенте есть числовые данные или пользователь просит «график / чарт /
диаграмму / визуализируй цифры».

---

## 1. Главное правило: сначала вывод, потом форма

Диаграмму выбирают НЕ от данных («у меня числа по месяцам → линия»), а от
вывода. Цепочка:

**Вывод (action title) → тип сравнения → форма диаграммы → семейство шаблона.**

Сформулируй вывод слайда одной фразой (Rule 2) — формулировка сама называет
тип сравнения: «доля X выросла» — покомпонентное; «регион A обгоняет B» —
позиционное; «GMV растёт третий квартал» — временнóе. Одна диаграмма — одно
сравнение; два сравнения в одном выводе → два слайда или два чарта
(`charts_compare`/`charts_duo`, если про одну мысль).

---

## 2. Пять типов сравнения → форма → семейство Еды

| Тип сравнения | Сигнальные слова в выводе | Классическая форма | Чем показываем в шаблоне |
|---|---|---|---|
| **Покомпонентное** — доля от целого | «доля», «X% от», «структура», «состав», «приходится на» | pie / 100%-stacked bar | Нативного pie нет — и по Желязны это не потеря. Одна главная доля → `hero` (крупное «61%») или `two_values`; 3–5 долей → `metrics` (значения-проценты) или BAR по долям (`charts_duo`, категории по убыванию); состав итога с точными цифрами → `datatable` |
| **Позиционное** — кто больше/меньше | «больше чем», «лидирует», «топ-N», «отстаёт», «рейтинг» | горизонтальный BAR | `charts_duo` (BAR-часть; категории по убыванию — акцент на первой) · сравнение по критериям → `compare` (таблица + hero-стата) · много элементов с точными значениями → `datatable` |
| **Временнóе** — динамика | «выросло», «упало», «тренд», «динамика», «с 2023 по…» | column (≤6–7 точек) / line (много точек, тренд) | `linechart` (LINE с датной осью, до 3 серий) · два периода по категориям → `charts_compare` (два COLUMN + дельта-бейджи) · суть в СОБЫТИЯХ, а не значениях → `timeline`, это не чарт-задача |
| **Частотное** — распределение | «распределение», «большинство в диапазоне», «медиана», «хвост» | гистограмма (column) | Нативной гистограммы нет: диапазоны как категории COLUMN (`charts_compare` / правая часть `charts_duo`) · точные корзины → `datatable` · вывод сжимается в одну цифру («80% заказов ≤ 30 мин») → `hero`/`metrics` вместо графика |
| **Корреляционное** — связь двух переменных | «зависит от», «чем больше X, тем…», «связь», «влияет» | scatter / paired bars | Scatter нативно нет: paired bars (`charts_duo`) · таблица (`datatable`) · часто честнее тезис с числами (`bodytext`: «в городах с X выше Y на 40%») или custom. Псевдо-scatter из подручных форм не рисовать |

Дальше по цепочке обычной: семейство есть → FILL/данные через `charts`;
формы нет в семействах → custom-HTML
([custom-html.md](custom-html.md), помни про конвертируемость); и custom
не берёт → честно скажи пользователю. Limitation-вопросов не задавать
(Rule 16): выбор формы — наша работа, в плане показывается как факт.

---

## 3. Когда диаграмма НЕ нужна

- **Вывод = одно число** → `hero` / `statement` / `metrics`. График из
  одной точки — не график.
- **Меньше 3 точек данных** → текст или метрики.
- **Точность важнее формы** (финансовая сверка, план/факт по строкам) →
  таблица (`datatable`), не чарт. В документ-режиме
  ([storyline.md](storyline.md) §0) это дефолт для финансового контента.
- **«График для солидности»** без вывода — не ставить (Rule 12: зачем
  слайд в деке).

---

## 4. Правила контента чарта

- **Заголовок чарт-слайда = вывод**, не название метрики: «GMV +25% за счёт
  регионов», не «Динамика GMV» (Rule 2). Метрика + единица + период — в
  подзаголовке/подписи (Rule 6).
- **Данные только от пользователя или проверяемого источника** —
  no-fabrication. Нет данных → intent-вопрос
  ([content-assembly-rules.md §3](content-assembly-rules.md)): «дай 4–8
  значений — или заменим текстовым блоком про тренд».
- **База сравнения видна** на слайде: подпись оси, дельта-бейдж, «vs Q1»
  рядом с числом (Rule 8).
- **Ось не обрезать для драматизации**: рост 2% не должен выглядеть
  ракетой. Динамический диапазон честный или разрыв оси явно объявлен.
- **Серии ≤3** (лимит шаблона), главная — одна, остальные — контекст.
  Категории BAR/COLUMN — короткие слова (узкие подписи переносятся).
- **Режим подачи** ([storyline.md](storyline.md) §0): выступление — минимум
  точек, одна акцентная серия, вывод читается за 3 секунды; документ —
  плотность допустима (чарт + таблица рядом, обе части `charts_duo`
  рабочие).

---

## 5. Нативность и повторяемость (движок)

Продукт скилла — РЕДАКТИРУЕМЫЙ .pptx: график пользователь должен мочь поправить
руками. Поэтому график берём из шаблона и заполняем ДАННЫМИ, а не рисуем шейпами:

- **Нативное заполнение работает** (`lib/charts.py`, `charts.*` в deckspec):
  `linechart`/`charts_compare`/`charts_duo` — движок переписывает категории/серии/
  встроенную xlsx через `replace_data`, тип/цвета/оси — дизайнерские, с readback-
  верификацией. Это ПЕРВЫЙ выбор для любых числовых серий (≥3 точек).
- **Никогда не рисуем чарт шейпами вместо нативного донора.** Псевдо-график из
  прямоугольников — не редактируемый и запрещён (custom-инфографика ≠ чарт).
  С 0.34.0 это ловит машинный гейт A17: SVG с ≥3 числовыми подписями в
  custom-слайде валит сборку (график картинкой не открывается через
  «Изменить данные»); осознанный глиф-декор без данных —
  `data-ppt-role="decor"` на `<svg>` ([custom-html.md](custom-html.md)).
- **Ограничение — нативные чарт-доноры НЕПОВТОРЯЕМЫ на дек** (по одному
  `linechart`/`charts_compare`/`charts_duo`). Причина — pptx-crash-check #6: два
  слайда, делящие chart-парт, роняют Mac PowerPoint в «Repair», а приватные
  копии партов проблему не сняли (нужен верифицированный в PowerPoint deep-clone
  с ремапом `c16:uniqueId` — открытый спайк `research/spike-2026-07-chart-
  cloning.md`). С 0.35.0 второй график той же формы БОЛЬШЕ НЕ тупик: нативный
  `data-chart` в custom ([custom-html.md](custom-html.md)) создаёт СВЕЖИЙ
  chart-парт (шаринга нет — краш-паттерн #6 не задевается); альтернативы
  прежние — таблица (`datatable`) или другое семейство сравнения.
- **Вторая линия — `data-chart` в custom (0.35.0):** редактируемый PowerPoint
  Chart со встроенной книгой строится движком из JSON: column/bar
  (+stacked), line, area, pie/doughnut. Это закрывает и часть «форм без
  доноров»: stacked bar/column, area, doughnut. Порядок строгий — сперва
  чарт-донор (дизайнерская рука в деталях), data-chart — когда донора
  нет, занят или форма другая; канон стиля брендов data-chart ставит САМ
  (0.38.0, снято с дизайнерских чартов: без сетки, без оси значений —
  цифры метками прямо на графике, плотная линия — только ключевые точки),
  цвета серий — accent-ряд темы. Комбо «столбцы + линия» — два
  data-chart рядом.
- **Чего по-прежнему нет** (нужен дизайнер или фабрика бренд-чартов, решение
  владельца): scatter, гистограмма как отдельная форма, водопад. chartEx-типы
  PowerPoint (нативный waterfall/funnel) python-pptx не создаёт —
  редактируемый водопад возможен только stacked-трюком фабрики или
  (по согласию) шейпами.
