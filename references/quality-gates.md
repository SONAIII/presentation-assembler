# Гейты качества — проверяем МЕРОЙ, потом глазом

Консолидация всех правил качества проекта: QA-чеклист, фит-стратегия по тирам,
накопленные уроки. Мета-правило проекта: **overflow / коллизии / выравнивание /
пустота — это ИЗМЕРЯЕМЫЕ вещи; глаз — последний слой, не первый.** Реальный кейс:
глазная проверка рендера дважды пропустила дефекты (переносы в узких плитках,
висящий бейдж), мера ловит оба.

## Пайплайн гейта (обязателен для каждого дека, порядок строгий)

1. **crash-check** — `python3 $SKILL_DIR/scripts/check_pptx.py <deck>` (вендорен) —
   файл не должен вызывать «Repair» в PowerPoint. Если Repair всплыл на чистом
   по чекеру деке — диагностический цикл: [pptx-crash-check.md](pptx-crash-check.md)
   + реестр паттернов [pptx-crash-known-issues.md](pptx-crash-known-issues.md).
2. **lint** — `python3 $SKILL_DIR/lib/lint.py <deck>` (exit 1 = HIGH, чинить обязательно):
   overflow по глифам (калибровано под PowerPoint), токен-шире-бокса, коллизии
   текст-vs-текст, пустые строки/трейлинг-br, шрифты/кегли-флоры.
3. **composition-check** (клон-генеративные слайды) — `generate.verify_timeline`
   для прямого таймлайна (пилюли по расчётной сетке, коннектор от первой до
   последней, eps 0.03") — встроен в сборку: кривой слайд не сохранится
   (плиточный `verify_tiles` ушёл вместе с плитками, 0.21.0). **Каждая НОВАЯ
   генеративная композиция обязана получить свой геометрический чекер ДО
   первого показа пользователю.**
4. **Рендер — два уровня.** Пиксель-приёмка: PowerPoint (macOS — AppleScript;
   Windows — COM-экспорт, 0.39.x по хэндоффу Ultima O6.4), эталонный движок —
   PP @110dpi даёт ~2934px по ширине. Скрининг: LibreOffice (любая ОС) — тот же
   чеклист B2–B14 по рендеру + перепроверка МЕРОЙ классов дефектов из реестра
   [lo-render-quirks.md](lo-render-quirks.md). qlmanage даёт 1600px и ВРЁТ про
   заливки/переносы — для приёмки запрещён. Совсем без рендера — самопроверка
   мерой (гейты 1–3), визуальный слой уезжает на STOP-просмотр пользователем.
   Уровень рендера — внутренняя кухня: дек подаётся пользователю как собранный
   и проверенный, без оговорок про рендер и ОС (правило 8 SKILL.md, Rule 16
   редполитики). Рендерить по одному, в фоне; PP клинит после серий
   (-9074/timeout). **Экономика времени (0.33.0)**: первый проход самопроверки —
   по контактному листу (`render.py --contact-sheet`, сетка миниатюр с
   номерами; полноразмерно — только подозрительные и все custom); после
   точечной правки — пересборка + `--slides N,M` (изменённые слайды и соседи),
   не пере-просмотр всего дека. И до ПЕРВОЙ сборки — примерка
   `scripts/fit_check.py deckspec.json`: реворд на чекере за секунды вместо
   кругов пересборки.
5. **Самопроверка по рендеру КАК ПОЛЬЗОВАТЕЛЬ** (чеклист B): B2 оптический
   баланс · B3 выравнивание по сетке · B4 воздух vs краудинг · B5 фото/кроп ·
   B6 заголовок = вывод/тезис, не тема · B7 цельность дека (заголовки 1→N — связный
   рассказ) · B8 «на бренде и намеренно» · B9 каждый текст НЕОБХОДИМ и в СВОЕЙ
   роли-слоте, тексты MECE (правило 17 редполитики; дисклеймеры/заполнители — cut) ·
   B10 контейнмент (user-правило 2026-07-03): каждый крупный текст/цифра лежит
   ЦЕЛИКОМ внутри своей карточки/плашки с дизайнерским отступом — по каждой
   карточке рендера явно спроси себя «край текста левее/правее края плашки?».
   Горизонталь ловится и машинно (lint `containment:text-outside-card`, HIGH =
   сборка падает); глаз по рендеру остаётся обязательным слоем — прежде всего
   на вертикаль (глиф выше/ниже плашки) и на текст внутри групп.
   Особый контроль там, где значение ДЛИННЕЕ дизайнерской заглушки («180+» вместо
   «34%», «45 тыс» вместо «12») — бокс мог вырасти за пределы плашки. Вылезло →
   чинить до показа (см. фит-стратегию ниже), не влезает штатными ручками —
   это баг движка: сказать владельцу скилла, дек пользователю как «готовый»
   не показывать. ·
   B11 якорная проходимость (user-правило 2026-07-16): за 3 секунды по рендеру,
   НЕ читая текст, считывается скелет слайда — сколько блоков и что они;
   каждый смысловой атом источника (бейдж, пилюля, подпись, лид-ин —
   [content-assembly-rules.md §1.0](content-assembly-rules.md)) виден ОТДЕЛЬНЫМ
   визуальным элементом, а не растворён в абзаце; по каждому абзацу длиннее
   двух строк внутри карточки явно спроси себя «это body или склейка атомов?».
   Слайд «полный», но одноуровневый там, где исходник был трёхуровневым, —
   НЕ прошедший слайд. ·
   B12 якоря низа чисты (фидбек-репорт 2026-07-20 «карточки накрыли номер
   страницы»): по каждому слайду явно спроси себя «свободна ли полоса
   футера/номера (нижние ~100px) и не упирается/не выходит ли контент за
   кромку канвы?» Контент заканчивается с воздухом до полосы; номер страницы
   виден и ничем не накрыт (исключение — санкционированные фото-панели до
   кромки, там номер ложится на фото у самих дизайнеров). Машинный слой для
   custom — гвард A15 (за канвой / в полосе номера = сборка падает); глаз
   обязателен для остальных веток. ·
   B13 вертикаль, слои и висячие слова (фидбек-репорт 2026-07: «коллизии и
   widow мимо гейта» — второй раунд подряд): по каждому слайду явно спроси себя
   (1) не наезжает ли 2-строчный заголовок на подзаголовок/фото (нарисованный
   низ текста — не габарит бокса); (2) не накрыта ли надпись залитой плашкой
   поверх неё (кейс hero: жёлтая плашка широкого значения легла на подпись);
   (3) нет ли заголовка с ОДНИМ словом на последней строке. Машинный слой:
   lint `collision:text-text` (наезд надписей), `collision:text-under-plate`
   (плашка поверх текста, HIGH), `widow:single-word-last-line` (MEDIUM);
   висячие слова движок склеивает nbsp сам (`defuse_widows`), неисправимое
   склейкой (два последних слова шире строки) остаётся и флагуется — нужен
   реворд. ·
   B14 атомы кастома = канон шаблона (правило владельца 2026-07-28, боевой
   прогон GR-дека: агент нарисовал красные ЗАЛИТЫЕ круги-бейджи под номера —
   у Городских такого атома нет): по каждому custom-слайду явно спроси себя
   «каждая подложка/бейдж/цифра существует на слайдах дизайнера?» Числа и
   номера — строго по канону шаблона (Городские: голая крупная цифра `.bignum`
   ЛИБО цифра в рамке-обводке `.numbox` — см. custom-recipes-gor-services.md
   «Числа и номера»); изобретённая подложка = дефект, чинить до показа.
   Только после этого — показывать.

## Заполненность и пустота (правила, введённые в проекте)

- **Мёртвая зона > 30% слайда → флаг** (A8): большие непреднамеренные пустоты —
  дефект композиции.
- **Fill-ratio дизайнерского слайда ≥ ~0.5:** готовый слайд подходит контенту, только
  если контент заполняет ~половину его ёмкости и больше. Совпало число элементов, но
  карточки на 75% пустые (короткие тезисы в био-раскладке) → это НЕ подходящий слайд,
  роутер обязан уйти в GENERATE. (Урок проекта — clone-elastic на «колонках».)
- **Перелив структуры — дефект той же тяжести, что пустота** (user-кейс
  2026-07-16): fill-ratio ловит НЕДОлив, а перелив — это когда в текстовый слот
  утрамбованы разнотипные смысловые атомы (бейджи, пилюли, подписи, лид-ины
  склеены в абзацы). Физические гейты такой слайд ПРОПУСКАЮТ (overflow нет,
  карточки полные) — дефект семантический. Отсечка: атомизация ДО сборки
  ([content-assembly-rules.md §1.0](content-assembly-rules.md), правило
  двустороннего соответствия) + якорный тест B11 по рендеру. Полный кейс —
  [common-mistakes.md](common-mistakes.md) «Смысловые атомы утрамбованы».
- **Плиточных композиций больше нет (0.21.0, решение владельца 2026-07-23)** —
  клон-композиции (прямой таймлайн, стат-сетка) наследуют геометрию
  дизайнерских юнитов донора; правила высоты/рядов плиток сняты вместе с веткой.
- **Контент живёт в контентной полосе канвы** (Еда: 1.74"–24.96" × 3.69"–13.63",
  заголовок на 1.1"; низ полосы = верх футера-якоря, контент до него, не в него) —
  не выше, не ниже, не шире.
- **Текст на плашке живёт внутри плашки.** Карточка/плашка — тоже канва: значение
  и подпись не пересекают её края (дизайнерский внутренний отступ сохраняется).
  Значение длиннее заглушки шаблона → проверка контейнмента по рендеру обязательна
  (B10); лечение — по контентному тиру (value → shrink группой до общего кегля,
  подпись → reword), геометрию плашки не трогаем.

## Фит-стратегия по тирам (разрешает конфликт shrink-vs-reword)

- **Структурный тир (обложка/раздел/содержание/закрытие/контакты) = точь-в-точь:**
  типографику дизайнера НЕ трогаем вообще (ни кегль, ни пер-абзацную иерархию).
  Не влезает → ПЕРЕФОРМУЛИРОВАТЬ текст, не сжимать. `slot_overflows` только флагует.
  **Санкционированное исключение (v0.16.0, фидбек F):** слот с `fit_policy:
  "text_shrink"` в спеке (CTA контактов) жмётся ЕДИНЫМ кеглем до объявленного
  `min_pt` — min_pt в спеке и есть санкция дизайнера; иерархия не ломается,
  кегль один на слот; замер с запасом ширины ~1.5% — заложенный буфер,
  намеренно шире фактического ~0.8% роста PP-vs-браузер (PP не кернит GPOS и
  набирает шире HB-метрик — пограничное слово иначе переносится раньше замера).
- **Контентный тир** (геометрия наша): число/значение → `shrink_to_fit` до min_pt
  (цифру не переформулируешь); проза → reword-first; body/буллеты → переполнение =
  сигнал РЕЗАТЬ или ДРОБИТЬ на слайды.
- **Кегле-флоры:** основной текст ≥ 24pt (таргет 28+), подписи ≥ 18pt. Шкала
  Еды: 32 → 28 → 24, ниже нельзя (источник `brand-tokens.type_scale_pt`).
- **Слово шире колонки → reword** (заменить слово / шире бокс / меньше колонок),
  НИКОГДА не делить слово и не давить кегль ниже флора.

## GENERATE-vs-SPLIT (плотность)

Большое N — генерируем на одном слайде, пока плотность на бренде (guard по
минимальной ширине/высоте юнита); за порогом — СПЛИТ на слайды с ребалансом
(5→3+2, 7→4+3), не «ужать всё».

## Редактура и типографика слайда (user-правила 2026-07-02)

- **Выбор разделителя.** Агенда-слайд с иерархией (активный пункт 115pt + прочие
  72pt, семейство `toc`; Еда: кегли — источник `agenda.json`) — это СЕКЦИОННЫЙ ОТКРЫВАТЕЛЬ для длинных деков
  (ориентир ~40 слайдов, ≥3 разделов): таких слайдов в деке столько же, сколько
  разделов, и в каждом выделен СВОЙ раздел (остальные — 72pt). Использовать его
  один раз в коротком деке нельзя — выглядит, будто выделенная тема важная, а
  остальные нет. Короткий дек (≲15 слайдов) → простой разделитель с одной темой
  (`divider`) или вовсе без разделителей.
- **Нумерация = последовательность (user-правило 2026-07-16).** Нумерованные
  табы (01/02…) и семейство steps — только шагам, этапам, приоритетам.
  Параллельные равноправные группы (например, «как меряем» и «роли») с
  номерами читаются как ложный порядок — смысловое искажение, чинить
  обязательно: другое семейство или custom-карточки без номеров.
- **Однородные значения — один кегль.** Метрики одного ранга (две цифры, стат-сетка)
  всегда одного размера: если одно значение ужато, чтобы влезть, — ужимаются ВСЕ
  до общего кегля. Машинно: `fill.value_group_pt` (минимум shrink-кеглей группы).
- **Смысловой заголовок важнее краткости.** Заголовок — вывод, не тема; если вывод
  не влезает в одну видимую строку, допускается 2 строки со сдвигом нижнего блока
  (`push_below` + `_apply_push_below`). Перенос делается ТЕКСТОМ
  (`wrap_to_visible`: сбалансированный разрыв, NBSP-склейки не рвём) — геометрия
  бокса не трогается НИКОГДА (placeholder от set-width вырождается в (0,0)).
  Резать заголовок до потери смысла нельзя.
- **Никаких висячих предлогов.** NBSP после коротких служебных слов (полный список:
  в/к/с/о/у/и/а/я, на/по/до/из/за/от/во/со/ко/об/не/
  ни/но/бы/же/ли/да, для/без/над/под/про/при/обо/изо/или/что/как/чем/тем).
  Числительные («два», «три») в список НЕ входят. Машинно: `_typo` в build_deck —
  автоматом на весь контент deckspec.
- **Самостоятельный абзац не заканчивается точкой.** Подписи, шаги, факты, карточки,
  описания этапов — без финальной точки (внутренние точки между предложениями
  остаются; «?», «!», «…» не трогаем). Машинно: `_typo` в build_deck.

## Повторы слайдов в деке (user-правило 2026-07-02)

- **Одиночки:** обложка — ровно одна на дек. Закрытие (CTA) и контакты — не больше
  одного каждого. Всё остальное повторяемо, КРОМЕ текстовых плашек (ниже).
- **Плашки с текстом не повторяются (user-правило 2026-07-13):**
  текстово-карточные структуры — columns / takeaways — каждая не больше одного
  раза на дек (плиточная генерация из атомов выпилена 0.21.0, семейства
  `reasons` больше нет). Машинная страховка A12: повтор текстово-карточного
  FILL — флаг.
  Причина: дек из однотипных плашек с текстом — типовая жалоба заказчиков;
  второй список показывай другим семейством, ревордом в иную форму или custom.
- **Повторы — сколько требует контент:** несколько таймлайнов / графиков / таблиц /
  сеток — нормально. Ограничители разнообразия: (а) не ставить ≥3 слайдов одного
  семейства ПОДРЯД без содержательной причины (линт-флаг A10 «монотонность»);
  (б) при повторе семейства чередовать дизайнерские ВАРИАНТЫ, если они есть
  (timeline: t3_first/t3_second/t4; columns: 4 варианта) — сначала исчерпываем
  варианты, потом дублируем один.
- **Агенда — регулярный повтор:** копий столько, сколько разделов; в каждой выделен
  СВОЙ раздел (`slots.active_index`), остальные пункты гаснут (72pt / полупрозрачные).
  Стили активного и обычного пункта снимаются С САМОГО дизайнерского слайда и
  переставляются — типографика не мутируется; перестановку проверяет машинный
  стилевой чекер (FAIL = дек не сохраняется).
- **Машинка (2026-07-02): повторы работают через безопасные клоны.** Дек собирается
  двухфазно: резолв по пристинному шаблону → каждый слайд дека = клон дизайнерского
  (lib/clone.py: ремап creationId/a16-GUID/modId, rels с сохранением rId, notesSlide
  не тащим), оригиналы уходят в keep_ordered. Ограничитель: слайд с chart/OLE-партом
  клонируется не более 1 раза на дек (known_issues #6 crash-check: шаринг chart-партов
  Mac PP не прощает, дублирование партов не лечит). ≥3 одного семейства подряд —
  предупреждение A10 при сборке.

- Данные чартов РЕДАКТИРУЮТСЯ (2026-07-02): `charts` в deckspec для linechart/charts_compare/charts_duo (см. SKILL.md) — тип чарта, цвета, оси дизайнерские. Мини-чарты think-cell (#30) — по-прежнему passthrough.

## Дисциплина рендера (уроки)

- Рендерить строго из `/private/tmp` (TCC/FDA-грабли).
- По одному деку за прогон, в фоне; батчи клинят PowerPoint.
- PP может быть занят пользователем — НЕ убивать процесс, попросить/подождать.
- Скриншоты >2000px давить `sips -Z 1500` перед чтением.
- Тихие сборки (`>/dev/null`) маскируют устаревшие файлы — сверять КОНТЕНТ файла,
  не только exit-код.

## Реестр машинных кодов (гварды сборки + линт)

Единый справочник кодов, которые печатает движок. Ground truth — код (не проза):
**новый гвард = следующий свободный номер A-серии + строка в этой таблице**;
